## 演算法（`scope_tool/analysis/`，只用 numpy）

- `measure.py`：輸入驗證（僅接受浮點型別、長度一致、有限值、時間遞增）、top/base 直方圖法（上下各 40%，
  眾數次數 < 5% 退回 max/min；同高峰取內側，Top 選較低格、Base 選較高格）、電壓量測（Vmax、Vmin、Vp-p、Vtop、Vbase、Vamp、Vavg、
  Vrms(DC)、Vrms(AC)）、量測清單與分派、統計（目前／平均／最小／最大／範圍／標準差／次數）。
  Vavg／Vrms(DC)／Vrms(AC) 預設 full（整段樣本），Web 可選 cycles（首末同向完整邊緣中閾交越之間的整數週期）；
  cycles 用相對時間、左閉右開，端點僅在局部 8 ULP 內吸附樣本；不足一完整週期回 No edges，不退回整段。
  Vavg 為樣本算術平均，AC RMS 扣除同段平均；均勻次取樣比例手冊未載明，保留全部樣本。
  cycles 從最左完整邊緣起至最後同向緣，與手冊觸發參考點單週期模式不同；Qt 使用 full。
- `edge.py`：閾值 10/50/90 或 20/50/80（% of top-base）；邊緣須依序穿越下中上閾值、線性內插；
  上升／下降時間與斜率優先只用 ≥ 4 點邊緣；皆不足時時間顯示上界 `<`、上升斜率下界 `>`、下降斜率 `<`（真值更負）；
  Qt 不將界限當精確值，改顯示點數不足原因；此界限處理為本程式與手冊差異。週期、頻率用同極性相鄰邊緣（預設上升，可選下降），
  頻率逐週期取倒數；±寬度、工作週期與 −工作週期（100 − 工作週期）逐週期配對，只算完整週期；
  過衝（Overshoot）＝邊緣後到平台中點的局部極值，前衝（Preshoot）＝平台中點到邊緣前的局部極值，
  皆除以 top−base。量測不出來時回傳原因。
- `mathfn.py`：加減乘除（時間軸不同時只取重疊區、B 內插到 A，不外插；除以 0 → nan）、
  反相、絕對值、平方、開根號、log10（以 1 個單位為參考，結果無單位，與原廠 dBm 顯示不同）、
  微分（np.gradient，無原廠 Low Pass／Align Phase 模式）、積分；推導單位。
- `filter.py`：低通＝4 階 Bessel-Thompson，H = 105 / P(j·2.1139·f/fc)，
  P(s)=s⁴+10s³+45s²+105s+105，補償群延遲；高通＝單極 jω/(jω+ωc)；平滑＝N 點移動平均。
  頻域套用，兩端以邊值補長（依 fc 決定長度），所需補長量超過原長時拒絕；平滑須等距且 N 為整數。
- `fft.py`：Rectangular、Hanning、Hamming、Flattop、Blackman-Harris；
  單位 dBm（預設）、Vrms、dBV、dBmV、dBµV、W，參考阻抗預設 50 Ω；
  原始資料加窗後前後補零至不小於原長的最小 2 冪，補零不提高實際解析能力；
  回傳 Δf、ENBW；PSD 換算用 ENBW，RBW 僅為顯示標籤（尚無 PSD 介面）；
  非電壓來源的 power 回 None；前 5 峰值；點數上限 2²⁴；須等距取樣。

- `marker.py`：Marker 提供帶正負號的 ΔY/ΔX；任一差值缺失、非有限、ΔX＝0 或比值非有限時回 None。
  Qt／Web 游標表均顯示 ΔY/ΔX（來源單位/s），缺值、差值非有限、ΔX＝0 或比值非有限時顯示空白。

## 版面（`scope_tool/ui/analysis_*.py`）

- 上方工具列（`analysis_controls.py`）：開啟、檔案資訊、重設視圖、通道歸位、游標歸位、匯出（選單內為原匯出列）、
  數學…、FFT 開關、閾值、量測範圍（游標區間／全部）、預覽、取樣率與點數摘要；放不下收進溢出選單。
- 左側直立分頁「時間量測／電壓量測」（`analysis_controls.py`）：點一下＝對目前選取通道加一筆量測，
  來源與邊緣方向在加入時固定。
- 通道列＋水平列（`analysis_chanbar.py`）：每通道色塊（顯示勾選、V/格、位置格數、雙擊換色、選取外框），
  F1/F2 同樣有色塊與刪除鈕；V/格（單位 V）只用查表檔位
  500 µV、2 mV、5 mV、10 mV、20 mV、50 mV、100 mV、200 mV、500 mV、1 V、2 V、5 V、10 V，
  其他單位用 1-2-5；水平列＝時間/格與中心位置，與主圖雙向同步。
- 主波形格（`analysis_plot.py`）：10×10 格；滾輪換 V/格前判斷，新檔位會讓波形超出 ±5 格就不放大；
  縮放以波形目前中心為準；示波器模式互動保留。
- FFT 頻譜格（`analysis_fftplot.py`）：FFT 開啟才出現，可拖分隔線；背景計算，舊結果丟棄。
- 結果區（`analysis_results.py`）：量測表（量測｜目前｜平均｜最小｜最大｜範圍｜標準差｜次數，
  右鍵刪除、清除全部、匯出結果 CSV）、游標表（t1、t2、Δt、1/Δt、v1、v2、ΔV、換算來源、各通道 @t1/@t2/Δ）、
  FFT 峰值表（Δf、ENBW、視窗、原始資料加窗後前後補零至最小 2 冪；補零不提高實際解析能力）；
  可收合；窄視窗改分頁。
- 數學對話框（`analysis_math.py`）：產生 F1、F2…，單位由分析頁的 {通道: 單位} 記錄；匯出 CSV 只含原始通道。

「目前」欄：最靠近顯示時間 t=0 的事件；切片不含 0 時取最靠近切片時間中點者，同距取較早。事件時間為起始邊緣中閾交越（延遲／相位用來源 1）；單值取範圍結果，無事件時間時退回首事件；先依通道 dx 與範圍切片決定顯示時間。其他統計不變，重算不累加次數。Qt 舊 stats(values) 未帶參考點，維持首事件。
（Infiniium 的 Current 是最近一次擷取，離線單檔沒有對應概念）。

## Jitter／眼圖（2026-10-17 第二輪，Claude × Codex 討論定案）

> 已於 2026-10-22 移出 GUI，程式碼暫存未接線

單一波形檔即可（Infiniium Real-Time Eye 本來就是折疊單次深擷取）。全部標明「固定頻率還原、近似、與 EZJIT 可能不同」。

- `clock.py` 時脈還原（只做固定頻率）：全自動（時脈＝同方向週期中位數；資料＝第一個顯著局部峰）、半自動（標稱速率當起點再擬合）、
  手動（UI 固定只估相位）。時脈與 NRZ 共用：相鄰邊緣間隔 ÷ UI 四捨五入累加成整數格號（只有單一邊緣位移造成的錯格不往後傳），
  中心化最小平方擬合 UI、t0，重複到格號不變（最多 10 次，否則報失敗）；TIE 平均為 0。
  相鄰邊緣位移差 > 0.5 UI 仍可能使格號永久漂移；格號全相同時報錯。
  單邊時脈 UI＝週期、兩邊時脈 UI＝半週期（保留 DCD）、資料一律兩種邊緣。
  既有 warnings 保留；新增三態與原因碼見下節。缺邊、TIE p-p > 0.5 UI、每 UI < 4 點仍只提示。
- `jitter.py`：TIE（時脈／資料）、N 週期、Period-Period（Pₖ₊ₙ − Pₖ 逐週期滑動）、±寬度差（相鄰週期脈寬相減）、
  還原 UI、還原速率。N 週期等只用時脈型且不跨缺邊；統計沿用量測表（標準差 σ＝去均值後的 RMS，母體 ddof=0，與含均值的 RMS 僅在均值為零時相等；範圍＝p-p）。
- `eye.py`：Vtop／Vbase＝UI 40–60% 樣本以中閾值分兩群；眼高＝(Vtop−3σ)−(Vbase+3σ)；Q＝(Vtop−Vbase)/(σtop+σbase)；
  交叉點＝TIE 迭代縮窄到 ±3σ；分欄揭露原始 σ、實測 p-p、裁切 σ、6σ 估計；眼寬＝UI−6×裁切 σ；
  Crossing %＝每個 UI 在交叉時間內插出的電壓取中段直方圖眾數（沒有明顯峰報無法判定）；DCD＝上升／下降 TIE 中位數差。
  色階圖：相位折疊到 −0.5～1.5 UI，相鄰取樣線性補點只供顯示（總點數上限 5e7、分塊累加，不截記錄），對數色階、黑底。
- 介面：工具列「Jitter」「眼圖」開關、「時脈…」設定（訊號類型、邊緣、速率模式、標稱速率、N，全頁共用）；
  左側量測欄第 3、4 頁「Jitter」「眼圖」；Jitter 格＝TIE 趨勢（缺邊斷開）＋直方圖；眼圖格＝色階圖；
  兩格與量測表共用來源範圍（游標區間／全部）與時脈設定；眼圖量測不必開眼圖格也會算。
- 檔案：`analysis/{clock,jitter,eye}.py`、`ui/analysis_{jitter,eye,runner,layout}.py`（runner、layout 自 controls／tab 拆出）。
  analysis_runner.py、analysis_layout.py 仍為一般量測／版面使用，不屬未接線範圍。
- 延後：資料型 N-UI／UI-UI、Explicit 外部時脈、PLL／SSC 追蹤、Jitter 頻譜、實測眼高、sinc 內插、RJ/DJ 分解、BER 浴缸、
  遮罩、等化、PAM、跨擷取累積。

## P1 量測狀態與原因碼（2026-10-23）

- `status.py`：`Result(status, reasons, diagnostics)`；三態 `valid / limited / invalid`。
  `worst` 取較差狀態（invalid > limited > valid）、原因碼聯集保序；同鍵 diagnostics 由後者覆蓋，不受狀態優劣影響；`to_dict()` 可 JSON 序列化且狀態保留英文。
  狀態顯示為有效／受限／無效，對照集中在 `STATUS_TEXT`；原因碼及繁體中文說明集中在 `REASON_TEXT`。Clock 原欄位與 warnings 保留，新增欄位皆有預設值。
- 兩層：Clock 還原狀態與單筆量測狀態；最終狀態合併取較差者。
  `jitter.measure`／`eye.measure` 維持 ndarray 簽名；並行 `jitter.assess(name, ck)`、
  `eye.assess(name, t, v, ck)` 回傳 Result。Jitter／眼圖 GUI 保留未接線；眼圖分別顯示「眼寬狀態」與「時脈狀態」，重複警告只顯示一次。
- 格號衝突 C＝最終相鄰跨度 ≤ 0 的數量，M＝邊緣數−1；C＝0 不因碰撞降級，
  0 < C < max(3, ceil(0.001 M)) → limited(GRID_COLLISION)，其餘 → invalid(GRID_COLLISION_MANY)。
  這是待校準的產品門檻，非物理界線，以具名常數保留。diagnostics 揭露 C 與門檻。
- 正跨度 gcd g > 1 → limited(RATE_AMBIGUOUS)，diagnostics 帶 g；
  全自動 NRZ 無給定速率 → limited(RATE_INFERRED)，UI／速率／眼寬／TIE 皆繼承。
- 半 UI 比例＝相鄰邊緣間隔／UI 的小數部分落在 0.5 ± 0.1（含端點）的比例。
  ≥ 1% 且 ≤ 5% → limited(HALF_UI_AMBIGUOUS)，> 5% → invalid；diagnostics 揭露比例及半徑。
  兩邊時脈先換算為 (相鄰邊緣間隔／UI − 1)／2，再計算半 UI 比例，與 warnings 共用奇數格換算；
  原始 0.5／1.5 UI 間隔不因此判為歧義。warnings 與狀態共用半徑 ±0.1、比例門檻 ≥1%（含端點）。
  邊緣 < 1000 → limited(LOW_EDGE_COUNT)；既有不足 3 緣、格號全同、不收斂等 ScopeError 不變。
- 高 jitter 滑格疑慮採聯合判據 E（`slip.py`）：TIE 對最終格號 n 做最小平方直線去趨勢，
  只供診斷，不修改原始 TIE。每 32 緣一塊，取完整區塊中位數 m，尾端不足一塊略過；不足三塊不偵測。
  jump[j]＝m[j+1]−m[j]；交界殘差取同一對區塊內（含交界）的最大 |r|，
  r＝_units−round(_units)，兩邊時脈沿用上述奇數格換算。
  A：交界左右各六塊的中位數差 >0.6 UI（頭尾用剩餘塊數），且單交界或含該交界的
  跨兩塊合計跳階 >0.5 UI，且 j−1..j+1 交界殘差至少一個 ≥0.35。
  B：相隔 1–5 個交界有方向相反、各自 >0.7 UI 的跳階，|和| <0.3 UI，
  兩端之間及緊鄰外側的交界 |jump| 均 <0.175 UI，且任一端交界殘差 ≥0.35。
  A/B 聯集計算命中交界數（B 的兩端皆計入）；TIE 含 NaN/Inf 時不判可疑，診斷值保持有限。
  ≥1 處 → limited(GRID_SLIP_SUSPECT)，不單憑 TIE 幅度或單調性判定。
  說明：「TIE 局部出現整 UI 跳變，且間隔接近半 UI 捨入邊界，格號可能滑格；TIE 統計僅供參考。」
  diagnostics 揭露 `grid_slip_suspects`、`grid_slip_max_block_jump_ui`（全部相鄰區塊的最大差）及區塊／門檻。
  數值均為具名的待校準的產品門檻；這是疑慮篩檢，不能保證檢出所有滑格。
  已知 E 版持久滑格漏報約 0.2%（較大樣本研究中，約 100 邊緣內跳回的 ±1 UI 短暫偏移）；
  此比例沿用研究結果，本輪小樣本自檢不重新估計。B 規則補強此類偏移，但不能保證全數檢出。
  大幅低頻 SJ 仍可能誤報：SJ 0.5UI/200UI＋RJ0.07 約 3–5%；20 seed 自檢上限放寬至 10% 以留餘裕。
  <96 邊緣不判定（<1000 已 LOW_EDGE_COUNT limited）；96 邊緣僅代表開始判定，不保證檢出。
  TIE 含非有限值時不判定滑格（放行方向）。
  小樣本自檢：clock.nrz、12000 UI、32 點/UI、seed 100–119，持久錯格定義為連續至少 128 邊緣。
- 交叉點原始 σ 與實測 p-p 使用全部 TIE；裁切 σ 與 6σ 估計使用迭代 ±3σ 結果。
  剔除比例嚴格 >1% 才讓裁切 σ、6σ 估計與眼寬 → limited(CROSSING_TRIMMED)，門檻為具名常數；
  ≤1% 只揭露資訊。原始 σ／實測 p-p 與 Crossing % 不因這個原因碼降級，仍繼承時脈狀態。
  diagnostics 一律揭露原始／裁切統計、剔除數、比例與比例門檻（比例以整數點數／總數計算，避免 1% 浮點邊界誤判）。
  crossing() 直接回傳剔除點數，不從保留比例反推。
  UI 一律顯示「資訊：剔除 N 點／x%」；>1% 才對裁切 σ、6σ 估計與眼寬顯示受限與「裁切 σ、6σ 估計與眼寬可能偏樂觀」。
  舊 RMS 名稱僅在 measure 入口轉為裁切 σ 的相容別名，不列入量測名稱或降級名稱集合。
  剔除比例顯示至小數三位（例如 201/20000＝1.005%）。
  舊「眼 Jitter p-p」改回實測 p-p；顯示名稱明確使用「眼 Jitter 6σ 估計」。
  σ < 1e-12 UI 不再裁切，避免浮點殘差造成假剔除。
- 眼寬 UI−6σ ≤ 0 → 主值 NaN、invalid(EYE_NO_POSITIVE_OPENING)，
  帶號值放 diagnostics["signed_width"]；文案「此模型未得到正開口」。
  不推論眼閉合或滑格，不回寫 TIE／還原速率狀態。
- 本輪未接線 Jitter／眼圖匯出。未來匯出時帶 `status`、`reasons` 欄，診斷資料可使用 `to_dict()`；
  本輪不修改 web、匯出程式及凍結契約。

- P2 全自動資料速率種子（`rate_seed.py`）：只取有限正間隔，不跨缺失時間重接。
  對數直方圖以 [1,2,3,2,1] 平滑計數，從左找超門檻連續 bin 簇，
  每簇所有局部極大值依間隔由小到大交給孤立短峰篩選，避免稀疏短記錄左緣雜訊使整簇被略過。
  平台須整段高於兩側才取左端；上升肩部如 3,5,5,7 的 5,5 不算極大值。
  預設用第一峰 ±2 bin 的原始間隔中位數作 1 UI 起點；若與下一峰（同簇或相鄰簇）符合 DCD 對，
  則各取兩峰 ±2 bin 原始間隔中位數 m1、m2，再取幾何中點 sqrt(m1×m2)，避免計數較大群拉偏。
  峰窗以排序後起訖索引保存；合併占比仍以聯集計數，重疊樣本只計一次。
  待校準常數 `_DCD_RATIO=1.55`：兩窗中位數比須嚴格小於 1.55；
  `_DCD_BALANCE=0.6`：較少的窗內原始計數至少為較多者的 60%（含等號）。
  1 UI／2 UI 比值 2、log 距 0.45 比值約 1.568，皆不合併。
  為避免長碼 2 UI／3 UI 被當成 DCD，只比較 2 倍頻：2m1 附近計數須至少為較少峰窗的 60%，
  且嚴格多於 DCD 假說預測的 2UI 短脈衝位置 m1+(m1+m2)/2 附近計數，才排除合併。
  `_CHAIN_WIDTH=0.08`（待校準）為兩位置的嚴格 ±8% 半窗，端點不計入；搜尋位置在 log 域計算以避免溢位。
  舊 any 版檢查 2、3、4 倍頻，會使 DCD≈0.16–0.21 的長碼退步（實測 1UI 占比 20%、30% 兩點）；比較式已修正此排除誤判。
  代價：人造碼長 {2,3,6}（缺 4、5）會合併得約 2.449，實際碼長連續時影響可忽略；
  {2,3,4} 若 4UI 只占 20%，也會合併成約 2.45，仍為殘留限制。
  短記錄 16–50 間隔仍採相同候選規則，不保證種子或完整 recover 正確。
  不用全域最小值或最大峰（眾數），後續格號擬合不變。
  待校準常數：對數 bin 寬 0.08、顯著門檻為最大平滑峰的 8%、最多 4096 bins；
  小於下一峰 0.6 倍且不超過 max(3, 正間隔數×0.5%) 的孤立短峰略過。
  正間隔 <16 才退回 min（diagnostics 註明 min_short_record）；其餘一律走相同的局部峰流程。
  diagnostics 揭露 seed_method（first_local_histogram_peak／min_short_record）、seed_peak_ui（秒）、
  seed_peak_fraction（所選峰窗或合併聯集的原始間隔占比；<16 間隔為 min 占比）、正間隔數與直方圖常數。
  已知限制：稀少 1 UI 長連續碼（1 UI 間隔 <約 3%）：結果可能為 limited 或 invalid（不會 valid），並帶滑格／半 UI 警示；請用手動或半自動。
  DCD 0.1／0.15／0.2 可因兩峰幾何中點改善起點；長碼仍取決於峰窗支持與比較式，不保證零錯格。
  平滑後僅剩單一峰／平台時無第二峰可合併；任意兩峰也無法僅靠間隔分布確認一定來自 DCD。
  DCD 約 ≥0.22 UI（兩子峰比值 (1+d)/(1−d) ≥ 約 1.55）不合併，全自動可能不收斂，請改用半自動。
  DCD≈0.21 且 σ≥0.05 時兩峰樣本比值可能越過 1.55 而不合併，結果為 invalid（實測 runs1-3 碼長 DCD0.21 σ0.05 為 8/10）。
  DCD 0.25 仍受此限制；現行（比較式）版與 any 版相同，σ0／.02／.03／.05 的完整 recover 皆 0/10，亦可能收斂卻錯格。
  短記錄 16／20 間隔 σ0.12：現行（比較式）版與 any 版相同，完整 recover 分別為 11/20、12/20（早期聯集中位數版為 12/20、12/20，低於更早的首峰版 14/20），仍未解決。
  只有 2/3 UI 間隔的資料種子為 2–3 UI（已知限制）。
  未觀測到 1 UI（例如全部為 4 UI 倍數）時仍無法推知真位元率，沿用 RATE_INFERRED 提示。

## Web FFT 的 RBW／VBW（P1，無 UI）

Auto（rbw=null）沿用整段 FFT 與舊 RBW＝df×窗 ENBW 倍率。手動 RBW 用 Welch 功率平均：L=round(enbw_bins·Fs/rbw)，夾到 [64,n]，n<64 時 L=n；50% 重疊，尾端不足 hop 捨棄；每段沿用原加窗、置中補零與 CG 校正，回實際 RBW＝ENBW＝enbw_bins·Fs/L，n 為全範圍點數。段分塊計算，不一次配置全部段。

VBW 為 null 或 ≥RBW 不平滑；否則在輸出單位域（dB 域亦直接平均）做移動平均，寬 RBW²/VBW，取奇數頻格並限制於陣列長度，兩端縮窗按實際點數正規化。此為本工具做法、待真機比對，非頻譜儀等效公式，亦不保證窄峰振幅不變。峰值／基準線／Track RF／包絡都使用平滑軌跡；平滑時峰值取格心不內插。Phase 不支援手動 RBW／VBW；非 null 必須有限且 >0。

## I3C 解碼（P1：純後端核心，2026-10-26）

依 `docs/archive/I3C解碼計畫.md.gz` 與 `docs/研究_解碼協定.md`，採 I3C Basic v1.2、單 lane SDR 的工程解析規則。只處理離線來源時間與完整原始樣本，不使用畫面包絡、不碰儀器。P1 提供 `web.logic`、`web.i3c_decode.decode`（兩線 Edges）與 `decode_waveforms`（共同時間軸及兩線電壓）；Analysis 快取、RPC、CSV 結果匯出及 UI 留待 P2–P4。

- 門檻：高低平台由既有 `measure.levels` 估計，中點 ±10% 平台差為下降／上升門檻，可手動指定有限且 lo<hi 的雙門檻。超過 4,000,000 點時用固定種子隨機抽樣估計平台，避免週期性等距抽樣混疊；邊沿抽取仍讀全部樣本。中間電壓維持前態；檔頭未定、NaN、Inf 為 unknown，缺值打斷前態。unknown 恢復標 resync，不製造 START／STOP／bit。無有限高低平台或無真實轉態時回 `ok=false` 並指明線名。
- 邊沿：每塊 2²² 點、前態跨塊延續，使用線性內插估計所跨門檻的時間；SCL 上升緣取當下 SDA，保留各 bit 實際時間。兩線同時刻轉換記 `ambiguous_edge`；最短完整 SCL 穩定段少於 4 點提示「取樣不足」。不濾 glitch、不做時序合規判定。
- Header：7-bit 位址、R/W、ACK；0x7E/W 後立即 Sr 為開場，併入後續 frame，並非缺少 code 的 CCC。0x7E/R 只在 ENTDAA 合法。0x02/W 的初始 START 為 Hot-Join，ACK／NACK 與後續 DAA 分開記錄，不在 HJ 時建立 DA。
- T：寫入為奇同位（資料八位與 T 的 XOR=1）；讀取是交握、不查 parity。T 視窗為第九位 SCL 上升至下一次下降：T=1 時 SDA 下降標「Controller 提前結束」並當 Sr；T=0 時 SDA 上升為 STOP。T=0 後無 Sr／STOP 又有至少八個資料時脈報 `t_bit`。擷取結束仍未 STOP、遇缺值或 pattern 中斷時，進行中 frame 標 `truncated`。擷取中途開始先報 `partial`，直到真實 START／STOP 才同步。
- 位址：只有本次擷取中成功的 ENTDAA／SETDASA／SETNEWDA 指派且未失效者是已確認 I3C DA；其他位址依 I3C 解讀並記資訊性 `type_unknown`。觀察到的位址為 `observed`，`t_from=null`，不捏造 PID，也不因後續流量自行升格。使用者明列 `i2c_addrs` 的位址優先用 I2C ACK／NACK 語意；I2C read 最後 NACK 為正常終止。
- IBI：初始 START 後 DA/R 標「IBI（亦可能為 Controller 直接讀）」。只有已知 BCR[2]=1 時首 byte 標 MDB；BCR[2]=0 卻有資料報 `ibi_unexpected_payload`，BCR 未知則保留 data 並提示。IBI NACK 是警告事件，不當成 parity 錯。
- CCC：表含研究所列常用碼及 ENTHDR0–7，並非完整 v1.2 CCC 全表。已知格式解讀 mask、長度、PID／BCR／DCR、DA 與 RSTACT；GETMXDS／GETCAPS／ENDXFER 保留 raw；未知碼不捏造名稱，記 `ccc_unknown`。Direct RSTDAA 0x86 記 `ccc_invalid`；ENTHDR1／2 標非 Basic。Direct 的 Defining Byte 必須／可選／禁止及長度由表判定，各 Sr 子段各自保留地址、方向、ACK；只有 ACK、格式及 T 正確才更新位址。SETDASA／SETNEWDA 的 DA 位於 [7:1] 且 bit0 必須為 0。GET 與既有值衝突記 `addr_conflict`、不覆寫；RSTDAA 結束所有有效位址項。
- DAA：64 位 PID／BCR／DCR 無逐 byte T，接七位 DA、位址奇同位、ACK。僅成功指派才建表，`t_from` 為 DA ACK 時間；最後 7E/R NACK 是正常結束。被動波形只能看到勝出者；合成器逐 bit 淘汰仲裁落敗者，下一輪才再參與。
- Pattern：保存完整 SCL 低期間，SDA 原本低時的第一個 setup 上升不計數。四次下降、SCL 再升時 SDA 低且隨後 STOP 為 HDR Exit；14 次轉換／七次下降、升 SCL 時 SDA 高且隨後 Sr、STOP 為 Target Reset。缺尾段標 `pattern_incomplete`，其他至少兩次下降的形狀標 `pattern_unknown`。只有完整 Reset 才在最後 STOP 結束所有有效位址並註「有效性未知」。只辨識形狀，未檢時序（tDIG_H 待確認）。
- HDR：ENTHDR 的 T 後只標「HDR-xxx 區段（未解碼）」，忽略內容；區段在 Exit pattern 起點結束，Exit 另成一筆，frames 依時間排序且不重疊。未見 ENTHDR 仍可辨識 Exit 並註記；未見 Exit 的 HDR 段標截斷。
- 上限：每線 10,000,000 個邊沿；任一線滿時兩線共用較早截止時間。最多 100,000 frames／100,000 fields，超過回 `truncated=true` 與截止時間警告；上限可由核心參數覆寫供自檢。bits 以 numpy 時間／值陣列回傳，不進事件摘要。

驗證以手寫 H1–H3、合成類比向量 1–40 與四種變異為準，效能包含類比判位與協定解析、不含合成器渲染時間。峰值 RSS 含 Python、numpy、輸入波形、合成及解碼暫存；獨立子程序分別量一次及連續五次。尚未與實測或示波器內建 I3C 解碼比對；自動門檻／遲滯寬度仍待真機校準。

已知限制：不解 HDR 內容／HDR Restart、CRR、多 lane、10-bit 位址；不辨識實際驅動節點／OD 或 PP 電氣切換，不做 glitch 濾波、deskew、時序合規或自動猜測 I2C。CCC 與版本相關的未確認格式只保留 raw。局部 Inf 與 NaN 一樣打斷並重新同步；「含 Inf 一律失敗」與計畫的 unknown 恢復規則不一致，因此無有限平台（全 Inf）回失敗，局部 Inf 保留可解碼的其他區段。P1 不存在 `_dec`，其失敗清空與 BAD_REQUEST 映射待 P2 驗證。

### HDR-DDR 補充（P7）

ENTHDR0 後至 HDR Exit 的區段依 SCL 上升及下降沿取樣，解出 Command、Data 與 CRC5，檢查 P1／P0、CRC、Token 及 preamble；首個 Data 的 NACK 與後續 Data 中止依各自語意收框。HDR-TSP／TSL 仍不解碼，HDR Restart 後的第二筆未涵蓋驗證。此實作**未經外部驗證，沒有實機波形**；CRC、同位與尾位的解讀仍待外部向量確認。以上 P1 原有 HDR 與已知限制敘述保留歷史背景，以此補充為目前行為。

## I2C 解碼

- 門檻：SCL／SDA 各用平台中點 ±10% 的遲滯門檻，可手動指定 lo<hi；自動估不出平台時提示改手動。中間電壓維持前態，NaN／Inf 打斷同步。只解已開啟檔案的完整樣本。
- 取樣：SCL 上升取 SDA，候選 bit 到下一個 SCL 下降才確認；遇 START／STOP 丟棄候選，避免控制時脈混入資料。每 8 位 MSB first＋第九位 ACK；最短 SCL 穩定段少於 4 點提示取樣不足。
- 狀態：每個 S／Sr 開一筆；支援 7／10-bit 位址，10-bit 讀須有同前綴的有效寫入脈絡。位址 NACK 後不解資料；寫資料 NACK 警告，讀末尾 NACK 正常。GC 無應答不算錯；START byte／Hs code 必須 NACK。S／Sr／P 打斷 1–8 位報 byte_cut，檔尾只報 truncated；S 後立即 P 為 empty。SCL 低期間 SDA 多次下降報 sda_glitch 並等下一控制條件重新同步。
- 原因碼：nack（未應答）、byte_cut（位元組遭中斷）、empty（空交易）、start_byte_ack／hs_code_ack（不應應答）、gc_invalid（無效 GC）、addr10_unresolved（10-bit 脈絡缺失）、reserved_addr（保留位址，資訊性）、sda_glitch（異常跳變）、truncated（擷取不完整）、ambiguous_edge（同時邊沿）。每線邊沿上限 10,000,000、frames／fields 各 100,000，超限共用較早截止點並警告。
- 顯示：位址 hex（10-bit 三位）、R/W、資料與 GC／START byte 名稱；單 lane 可放大逐 bit，報告帶門檻摘要。不做 SMBus／PMBus、Device ID 拆解、Hs／UFm 時序、去毛刺、時序合規、仲裁或 8-bit 位址顯示。
- RS-485：TX−／RX− 可省，負端須搭配對應正端；門檻只設定相減後的 TX／RX，手動建議 −0.2／+0.2 V。A／B 命名可能因晶片而異，依波形使用反相。三態時若差動落在遲滯帶內則維持前態；failsafe 偏壓不足時可能出現 unsynced。
- 實機依據：X6000A H5 的 SDA=CHAN1、SCL=CHAN3，取樣間隔約 1.55 µs；以實機序列表核對資料與缺 ACK，時間容差取取樣間隔與 CSV 捨入量較大者。BIN 為 H5 每 33 點取一，取樣不足，不用來驗解碼。

## SPI 解碼

- 通道：SCLK 必填，MOSI／MISO 至少一條，CS 可省；各線自動或手動遲滯門檻。固定電位線使用手動門檻。
- 格式：Mode 0–3、字長 4–32 位、MSB／LSB 先與 CS 高／低有效均由使用者指定；無 CS 可設定閒置分框時間，未指定時整段一框。Mode 0／3 取上升緣，Mode 1／2 取下降緣。
- 交易：CS 有效區段內每字長組一字；殘餘位標 incomplete，檔案邊界 CS 有效標 truncated，時脈相位不符標 clk_phase，未知位標 unknown_bit，無 CS 標資訊性 no_cs。CS 外時脈只計數。只保存 MOSI（若未接則 MISO）的逐位資料；雙線標註列顯示兩條字組。
- 限制：不做 3-wire、Dual／Quad、去毛刺、自動格式偵測、時序量測或命令解讀。合成與手寫向量驗證，待實機驗證。

## UART 解碼

- 通道與門檻：TX 必填、RX 可省，兩線獨立解碼；平台中點 ±10% 遲滯，可手動 lo<hi。手動門檻允許 RX 全段閒置；自動估不出平台提示改手動。反相僅翻轉 0／1，不改門檻或 X；RS-232 勾反相，RS-485 可用差動探棒、單端近似，或選擇負端通道進行相減。
- 取樣與格式：鮑率必填正數，資料位 5–9、同位 N/E/O/M/S、停止位 1/2，預設 115200、8N1、不反相。位元中心取樣、LSB first，不做多數決；每位少於 8 點警告，NaN／Inf／未定或截止點外為 X。
- 狀態：HUNT 須先連續 ≥1T mark；X 清除 mark。false start 中點不是明確 0 時不出字元、不消耗區間，須重新累積 mark。完整候選消耗到最後 stop 中心；HUNT 遇無效 stop 只報 unsynced，SYNCED 遇 framing 回 HUNT。SYNCED 接下一下降緣不要求 1T mark；兩個 stop 都須有效，過短另記 short_stop。
- BREAK：資料全 0、第一 stop 為 0，且低電位 ≥完整字元時間；輸出 BREAK 而非 00，不另報 framing。等上升緣後回 HUNT、重新要求 mark；檔尾截斷加 truncated。相鄰字元閒置 ≤2 字元時間併組，TX／RX 重疊組取聯集，frames 排序不重疊。
- 原因碼：framing（停止位錯誤）、parity（同位錯）、short_stop（停止位過短）、break（中斷，正常事件）、truncated（擷取不完整）、unsynced（未同步，警告）、unknown_bit（未知位元）。framing 超過 10% 提醒確認鮑率／格式，閒置偏低時提示反相。每線邊沿 10,000,000、frames／fields 各 100,000，共用較早截止點並警告。
- 顯示：事件表列 TX／RX hex 與 ASCII，錯誤加 ⚠；只有 TX 可逐 bit，雙線為上 TX／下 RX，只到字元；bits 僅存 TX。報告帶送出時鮑率、格式、反相與門檻快照。不做自動鮑率／格式、1.5 stop、寬鬆 stop、Modbus、DE／衝突／回音、去毛刺或 9-bit 位址語意。
- 實機依據：X6000A H5 為 TX=CHAN1、RX=CHAN3、低電位閒置，須反相。完整字元支持 19200 8O1；儀器 CSV 行為則符合 8N1（把第九位作 stop，Unknown 對應 framing）。核心遵守 HUNT 規則，不能逐列仿製儀器錯誤後的接收策略；首列擷取前半字元不猜值、末列截斷。詳見實機分析文件附錄。

## CAN 解碼

支援 Classical CAN 2.0A／B 資料框與遠端框，顯示 ID、DLC、資料、CRC、ACK 和錯誤旗標；CAN FD 僅標示，尚不解碼。可選 CANH 或差動訊號，亦可加選 CANL 做差動相減；可設定位元率、取樣點與顯性電壓。取樣採無 SJW 限制的逐邊沿重對齊，屬離線工程近似；不判定節點或仲裁歸屬。實機 CSV 序列表僅供合成閉環比對，並非原始波形的判位驗證。

CAN FD 選項：資料段位元率留空時僅標示 FD；填入正數後可設定資料段取樣點（50–95%，預設 75%），供 ISO CAN FD 解碼使用。CAN FD **未經外部驗證**。

## eSPI 解碼

第一版以 CS 低有效切分交易，在 CLK 上升緣取樣 IO0 命令與 IO1 回應，只支援單線 I/O。每筆顯示命令、回應、等待、狀態與 CRC；兩個轉向時脈不列入欄位。CRC-8 使用多項式 0x07、初值 0、MSB 先；可關閉驗證。狀態低位元組先傳，保留位非零會警告。RESET 為連續 16 個 1。未知命令以原始資料顯示；截斷和未知位元會標示。

支援 XML 所列命令與 short 命令；保留的 short 編碼視為未知。PUT 的已知 cycle type 依 XML 計算長度，未知 cycle 不猜測；附加通道回應尚未解析，標示資料不完整。GET_CONFIGURATION 的 ACCEPT 回應包含四個資料位元組。Dual／Quad、Alert、自動切換模式、通道封包細解與自動判斷 CRC 關閉均不支援。尚無實機波形，結果未經實機驗證。

## USB PD 解碼

選擇一條 CC 通道；預設逐封包以前導碼估算位元時間，也可手動輸入正數位元率。以 BMC 邊沿間距還原位元，辨識 SOP、SOP′、SOP″、Debug ordered set、Hard Reset 與 Cable Reset，再解讀 4b5b、訊息標頭、最多七個 32 位資料物件、CRC32 與 EOP。訊息名稱依 USB PD 3.1 XML 列舉；資料物件目前顯示原值，Extended Header 與 Chunk 不細解。

錯誤及不完整封包保留原因供檢視；位元率超出 300 kbit/s ±20% 顯示警告。前導碼尋框要求四個 ordered set 符號全部正確。此版未實作 GoodCRC 配對、協定狀態機、PDO／VDM／EPR 內容、CC1／CC2 自動辨識或 VBUS 關聯。尚未以實機波形驗證，建議擷取充電協商序列並使用至少 10 MSa/s。

目前尚未檢查 SOP 類型與訊息型別的相容性，保留值檢查限訊息型別及規格版本；封包末位缺少收尾邊沿時尚未補邊沿。這些情況的結果需人工確認。
