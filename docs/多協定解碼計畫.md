## 2. 第 0 步：共用層依協定註冊（序列，先做；完成後四條線才開工）

目標：四協定之後**只新增檔案**，共用檔只多一行 `decode_protocols.js` 的匯出。I3C 解碼結果、畫面、CSV、報告不變。

### 2.1 `web/logic.py`（追加，不改既有函式）
```python
MAX_FRAMES = 100_000
MAX_FIELDS = 100_000
def levels_at(e: Edges, t: np.ndarray, end: float) -> np.ndarray
    # 每個 t 的邏輯值＝最後一個 time ≤ t 的邊沿值；t 早於第一個邊沿或 t > end → -1（X）
def prepare(t, volts: dict[str, np.ndarray], thresholds: dict, *, require_edges: bool,
            max_edges=MAX_EDGES) -> tuple[dict, dict, float, str | None]
    # 回 (edges, used, end, reason)
```
- **固定電位線**：`require_edges=True`（只有 I3C）維持現行政策——無有限平台或無真實轉態即具名失敗，訊息與 `analysis_decode.py:66/:73` 逐字相同。`require_edges=False`（四個新協定）：**手動門檻下允許整段無轉態**（SPI MOSI／MISO 全 0／全 1、整段有效的 CS、閒置的 UART RX 都合法）；只有「自動門檻估不出平台」才失敗，訊息加「；請改用手動門檻」；手動門檻下整段都未定（無任何非 −1 邊沿）也失敗（「XX 全段未定」）。
- **有效截止點 `end`**：`prepare` 統一計算＝`min(t[-1], 各截斷線最後邊沿時間)`（即 `i3c_decode.py:229-232` 的規則搬到共用層）。`prepare` **不產生 warnings**；「邊沿超過上限，只解到 t=…」的唯一加入位置是各協定的 `run`：I3C 照舊在 `i3c_decode.py:257-258` 加，新協定比照（`any(e.truncated for e in edges.values())` 時加同一句），`analysis_decode` 也不再加，避免漏報或重複。`analysis_decode` 以 `t1=end` 呼叫各協定 `run`；**新協定不得取樣或產生晚於 `t1` 的 bit／字組／字元**，跨過 `t1` 者標 `truncated`。I3C 照舊自行計算同一值，結果不變。
- `levels_at` 給 SPI／UART／CAN 在「取樣時刻」查遲滯後狀態（resync 邊沿是狀態不是轉態，照樣算），向量化 `searchsorted`；`end` 之後一律 X，杜絕截止點後的虛構資料。
- `prepare` 給 `analysis_decode` 與各協定 `_check` 共用，避免四份重複的「門檻→邊沿」。

**`decode()` 泛化流程**（取代 `analysis_decode.py:27-79`）：
1. 鎖內清 `_dec`（照舊）→ `mod = protocol(protocol)`。
2. 驗 `channels`：dict、鍵 ⊆ `ROLES`、必填齊全、值為字串、彼此不同、通道存在。驗 `thresholds`：鍵**恰為**邏輯線名（給定角色去掉 `DIFF` 的負端），值 null 或兩個有限數 lo<hi。`mod.options(options, channels)` 的 ValueError → BadRequest。全部在 job 內 → job BAD_REQUEST（同現況）。
3. 所有通道對 BASE 通道 `validate_time`（整條 `array_equal`，同現況）。
4. 每條邏輯線取電壓；有負端時 `pos − neg`（CAN 的 CANH−CANL 用）。`# ponytail: 相減配置一份整條陣列；1e8 點時 +800 MB，需要時改 to_edges 分塊相減`。
5. `logic.prepare(require_edges=mod.REQUIRE_EDGES)` → 失敗回具名失敗摘要（格式同現況）；成功 `mod.run(edges, t1=end, max_frames=MAX_FRAMES, max_fields=MAX_FIELDS, **opts)`（`end`＝§2.1 的共同有效截止點）。
6. 摘要／`_dec` 寫法同現況；`_dec` 多存 `protocol`、`base`（BASE 角色對應的通道名）。

**CSV**（`export_decode`）：meta、事件表欄名**完全不改**（I3C 輸出不變；其他協定的「第9位／第9位意義」欄＝`ninth／ninth_kind`，即附加位）；位址表段只在 `ADDR_TABLE` 為 True 時輸出。

## 3. I2C

### 3.1 通道與參數
- 角色：`scl`（必填）、`sda`（必填）；BASE＝`scl`。參數：**無**（`options={}`）。門檻自動＝平台中點 ±10%（研究 I2C §2.1 建議 0.3／0.7 VDD，可手動覆寫）。
- 已做：`addr_bits`（7／8，預設 7）。7 沿用位址＋W/R；8 的一般 7-bit 位址含 R/W（如 0x50 寫→0xA0、讀→0xA1），標註列為 A0／A1，事件表與報告保留 R/W 欄，CSV 位址同步。顯示使用送出選項快照；10-bit、General Call、START byte、Hs 控制碼及保留位址維持原顯示，frames 資料不變。

### 3.2 狀態機（`web/i2c_decode.py`）
**沿用**：`i3c_events.events(scl, sda, end)`（START／STOP 判定、SCL 上升取 SDA、gap／resync、ambiguous）、`i3c_fields.frame()／field()`（I2C 正好是 MSB first、無 X）、`i3c_ccc.reason()`。不改這些檔。I2C 是唯一 `levels_at` 用不到的新協定；`end` 照樣由 `run` 的 `t1` 傳給 `events`。
- **位元延後確認**（研究 I2C §7.2）：`bit` 事件先放 `pending`，收到下一個 `low`（SCL 下降）才併入 byte；遇 `start`／`stop` 丟棄 `pending`（那是控制器為 STOP／Sr 拉高 SCL，不是資料）。
- 每 9 bit：8 bit MSB first＋ACK（0＝ACK）。第一個 byte 為位址 byte：`addr7=b>>1`、`rw=b&1`。
- 位址分類（研究 I2C §7.4）：`0x00/W` General Call（第二 byte：0x06／0x04 標名稱；0x00 → `gc_invalid`；B=1 → 「hardware GC」附來源位址；其他值只標 hex）；`0x00/R` START byte（ACK → `start_byte_ack`，之後 Sr 才是真位址）；`0x01–0x03`、`0x7C–0x7F`（含 F8／F9 Device ID 前綴）→ 照常解、加資訊性 `reserved_addr` 與用途 label；`0000 1xxx` → kind `hs_code`（label「Hs controller code」，之後照常解，不換時序）；`11110xx` → 10-bit 前綴（研究 I2C §4.2 規則 1–6：寫方向第二 byte 為 A7..A0；Sr 後同前綴＋R 且脈絡有效 → 10-bit 讀，下一 byte 為資料；脈絡失效 → `addr10_unresolved`）。
- **ACK／NACK 判定表**（第 9 位；研究 I2C §3.2、§4.4、§4.5、§6.1、§8.2）：

  | 位元組 | ACK（0） | NACK（1） |
  |---|---|---|
  | 一般 7-bit 位址（W 或 R） | 正常 | `nack` warn；之後到 Sr／P 前的時脈不解資料 |
  | 10-bit 前綴 A1（W） | 正常 | `nack` warn，label「A1」；不虛構第二 byte |
  | 10-bit 低位址 A2 | 正常 | `nack` warn，label「A2」 |
  | 10-bit 讀前綴 A3（Sr 後 `11110xx R`） | 正常 | `nack` warn，label「A3」 |
  | 寫資料（含 GC 第二 byte 以外） | 正常 | `nack` warn，之後照常解（I2C 不因 NACK 自動 STOP） |
  | 讀資料（控制器回應） | 正常（繼續讀） | 正常結束（最後一 byte），**無** reason |
  | General Call 第一 byte／第二 byte | 正常 | 不算錯（可能沒有目標需要），只寫 label「無目標應答」 |
  | START byte `0x01` | `start_byte_ack` error | 正常（規定不得 ACK） |
  | Hs controller code `0000 1xxx` | `hs_code_ack` error | 正常（規定送 NACK） |

- **缺第九位**：byte 已收 1–8 bit（含「8 個資料位都到了、第 9 位沒到」）就遇 S／Sr／P → `byte_cut` error，field `nbits`＝實收位數、`ninth=null`；擷取結束時同情況 → 只標 `truncated`（擷取限制，不是傳送錯誤）。byte 邊界（第 9 位之後）的 P 正常。S 後立即 P → kind `empty`、`empty` warn。
- `pattern` 事件（同一 SCL 低期間 SDA 下降 ≥2 次；I2C 不應出現）→ 結束進行中 frame（`truncated`＋`sda_glitch`），回未同步，等下一個 START／STOP。
- 擷取中途開始、gap、擷取結束未見 STOP：同 I3C（`partial`、`truncated`）。
- 遲滯判位不會產生中間值 X，研究 I2C T33／T35（ACK 位於 0.3–0.7 VDD）在本架構不適用，不做。

### 3.3 frame／field 對應
- frame：`kind`、`start`（S／Sr）、`addr`（7 或 10 bit 值）、`rw`、`ack`（位址 ACK）、`label`。一個 S／Sr 開一筆（Sr 分開「寫」與「讀」兩筆，同 I3C private transfer）。
- field：`addr`（9 bit，value＝位址 byte 含 R/W，`ninth_kind='ack'`）、`addr_lo`（10-bit 第二 byte）、`data`；標註列第 9 位小標沿用 `A／N`。
- 列舉（第 0 步寫入契約）：
  - `DecodeFrame.kind.i2c`：`write read gc start_byte hs_code empty partial`
  - `DecodeField.kind.i2c`：`addr addr_lo data`
  - `DecodeFrame.reasons.i2c`：`nack byte_cut empty start_byte_ack hs_code_ack gc_invalid addr10_unresolved reserved_addr sda_glitch truncated ambiguous_edge`（`reserved_addr` 為資訊性，不改 status）
- 前端 `decode_i2c.js`：columns＝位址（hex，10-bit 三位）、R/W；content＝data hex（NACK 前加 ⚠）＋GC／START byte 名稱；fieldText 同 I3C。單 lane。

### 3.4 合成器與測試向量（`web/i2c_synth.py`、`web/i2c_check.py`）
- 符號層**自寫，不沿用 `i3c_synth.Bus`**：`Bus.start／rstart／stop`（`i3c_synth.py:25-48`）的延遲寫死 20／40 ns，不隨 `f_pp` 縮放；Codex 以 100／400 kHz 加 `tr=300 ns` 渲染重現，`events` 只找到第一個 START、找不到 Sr／STOP。`i2c_synth.py` 的 START／Sr／STOP 以 SCL 週期縮放（tHD;STA、tSU;STA、tSU;STO 各取 ½ 週期，STOP 後 tBUF 取 1 週期），資料位比照 `Bus.bit` 的做法（SCL 低期間 ¼ 週期處變更 SDA）；提供 `start／rstart／stop／byte(v, ack)／stretch(sec)／idle／raw`，記錄真值。凍結的 `i3c_synth` 不動。渲染用 `synth.render`（`tr=300e-9`、fs 20 MSa/s）。自檢先斷言：100 k 與 400 kHz 的「寫→Sr→讀→STOP」經 `events` 得到 S、Sr、P 各一。`fixture(path)` 產生瀏覽器用 2 通道 CSV（約 20 萬點，含 T01、T02、T03、T07、T08、T11、T13、T21）並回 `{channels, options, expect_kinds}`。
- 手寫真值：H1＝研究 I2C T01 逐 bit 轉換清單；H2＝T08（10-bit 讀）。
- 向量（研究 I2C §11 編號）：T01–T14、T15（Hs code NACK 正常、資料照解；另一筆 Hs code 被 ACK → `hs_code_ack`）、T17（延展 2 ms，資料不變）、T20、T21、T31、T32、T34；ACK 表逐列各一（讀方向位址 NACK、GC 無應答不報錯、讀最後 NACK 無 reason）；10-bit A1／A2／A3 NACK 各一（label 分別正確）；缺第九位：8 位後 STOP、8 位後 Sr → `byte_cut`，8 位後擷取結束 → 只 `truncated`；另加：雜訊 σ=5%、20 seed 結果相同；NaN 段 → 前 frame `truncated`、之後重新同步；取樣不足（每 SCL 半週期 <4 點）警告；SCL 低期間 SDA 兩次下降 → `sda_glitch`；上限（參數調小 MAX_FRAMES／MAX_FIELDS，以及調小 `prepare(max_edges=…)` → 兩線共同截止、截止後無 frame）；效能 10M 點×2 ≤15 s（印耗時）。
- 不做的研究向量：T18／T19（glitch 濾波）、T22（時序）、T23／T24／T26／T27／T29（SMBus）、T25 Device ID 欄位拆解（只標保留位址）、T28／T30（卡低報告）、T33／T35（不適用）。
- `--mutations`：ACK 極性反相、拿掉 `pending` 延後確認（T32 必紅）、10-bit 讀把第二 byte 當位址（T08 必紅）。

### 4.2 狀態機（`web/spi_decode.py`，以 numpy 為主）
- 取樣緣：`rising = (cpol == cpha)`（Mode 0／3 上升、1／2 下降，研究 SPI §3.2）。取 SCLK 邊沿中該方向且非 resync 者為取樣時刻；CPHA=1 的第一個（移位）邊沿自然不被取樣。
- 資料值：`logic.levels_at(mosi, t_sample, t1)`（向量化）；值 −1 → X。只取 `≤ t1` 的取樣緣；跨過 `t1` 的字組／交易標 `truncated`。
- 固定電位合法：MOSI／MISO 全 0／全 1、CS 整段有效（手動門檻）照常解；CS 整段有效＝一筆從檔頭到 `t1` 的交易，兩端 `truncated`。
- 字組 value 在本檔依位序組合並處理 X（**不用** `i3c_fields.field()`，它固定 MSB first），直接組 field dict。
- **有 CS**：CS 邊沿切出有效區段；區段內取樣點依序每 W 個組一字；區段結束有殘餘 bit → 不完整字組（`incomplete`）。擷取開始時 CS 已有效 → `truncated`（label「擷取開始時 CS 已有效，對齊未知」）；擷取結束時仍有效 → `truncated`。CS 有效瞬間 SCLK 位準 ≠ CPOL → `clk_phase` warn。CS 外的 SCLK 只計數，寫進 `warnings`（「CS 外時脈 N 個」），不成 frame。
- **無 CS**：`idle` 為 null → 整段一筆；否則相鄰 SCLK 邊沿間隔 > `idle` 即分框（研究 SPI §3.4，開框看任一 SCLK 邊沿）。一律加資訊性 `no_cs`（「無 CS：字組對齊未驗證」）。
- 含 X 的字組 → `value=null`、`ok=false`、label 以遮罩顯示（如 `0x5?`）、frame 加 `unknown_bit`。

### 4.3 frame／field 對應
- frame：`kind='txn'`，`t0／t1`＝CS 有效起訖（無 CS 為該框首末取樣緣），其餘欄 null。
- field：每字組每條資料線一個，`kind='mosi'`／`'miso'`，`nbits`＝實收位數，`ninth_kind=null`。
- bits：只存**主線**（有 MOSI 用 MOSI，否則 MISO）的取樣點，時間嚴格遞增。
- 標註列：MOSI、MISO 都有 → 雙 lane（上 MOSI、下 MISO，只到字組不進逐 bit）；只有一條 → 單 lane（上 frame、下字組、放大逐 bit）。`# ponytail: 雙線時不顯示逐 bit；需要時 bits 改存兩線`。
- 列舉：
  - `DecodeFrame.kind.spi`：`txn`
  - `DecodeField.kind.spi`：`mosi miso`
  - `DecodeFrame.reasons.spi`：`incomplete truncated clk_phase unknown_bit no_cs`（`no_cs` 資訊性）
- 前端 `decode_spi.js`：columns＝字組數；content＝`MOSI 9F 00 00／MISO FF EF 40`（64 字截斷沿用）；summary（取自 options 快照）＝`SPI Mode 0 · 8 bit MSB · CS 低有效`。

### 4.4 合成器與測試向量（`web/spi_synth.py`、`web/spi_check.py`）
- 符號層：`spi_bus(words, mode, bits, lsb, cs=True, cs_active='low', gap, t_bit)` 產生 sclk／mosi／miso／cs 轉換（資料在移位緣變化）與真值；`synth.render(lines=('sclk','mosi','miso','cs'))`。`fixture(path)`：4 通道 CSV，含 T1、T5、T7、T8。
- 手寫真值：H1＝研究 SPI T1（Mode 0，MOSI `10010110`、MISO `00101101` → 0x96／0x2D）逐轉換手寫。
- 向量（研究 SPI §8）：T1、T2、T3a、T3b、T4、T5、T6、T7、T8、T11a（MISO 前段 NaN → X）、T12、T12b、T13a、T13b、T14、T14b、T17、T21、T23；另加：CS 高有效；**固定電位**（MISO 全 1、MOSI 全 0、CS 整段有效，手動門檻 → 解得出、不失敗；自動門檻 → 具名失敗含「請改用手動門檻」）；縮小 `max_edges`（SCLK 先截斷 → 截止點後無字組、無虛構資料）；雜訊、上限、效能 10M 點×4 ≤15 s。
- 不做：T9／T10（去毛刺）、T11b（不適用：遲滯保持前態）、T15／T16（3-wire）、T18–T20、T22（自動偵測）、T24（Dual／Quad）。
- `--mutations`：取樣緣表改為只看 CPHA（T2／T3b 必紅）、位序反轉（T4 必紅）、字組滿 W 後不歸零（T12b 必紅）。

### 4.5 明確不做
3-wire 半雙工、Dual／Quad、去毛刺 Dg、CS 毛刺處理、CPOL／CPHA／字長／位序／CS 極性自動偵測、setup／hold 量測、命令層解讀（Flash 指令等）、雙線逐 bit。

## 5. UART（TTL／RS-232／RS-485）

### 5.1 通道與參數
- 角色：`tx`（必填；只接一條線時放這裡）、`rx`（可省）；BASE＝`tx`。兩線各自獨立解碼。
- 參數（預設）：`baud`（必填，bit/s，`<datalist>` 常用值 9600…921600、1000000）；`bits` 5–9（8）；`parity` `N E O M S`（N）；`stop` 1／2（1；1.5 → `options()` 拒絕，研究 UART U32）；`invert` 反相（false）。
- 電氣：TTL 不反相；**RS-232 勾反相**（負電壓＝1）；RS-485 以差動探棒（或單端 A／B 近似）接入，極性不對就勾反相。UI 在反相旁加說明，不另做電氣 profile 下拉。門檻自動（±12 V 時約 ±2.4 V），可手動。
- 鮑率估計：**已做：手動觸發的估計按鈕；解碼本身仍須明確鮑率**（2026-10-27 使用者推翻原 Q2）。依目前 TX／RX 與門檻各估一次，以符合比例、有效間距數選較有把握者；反相不影響邊緣間距。濾除短於兩取樣間隔的間距，至少 8 個；標準鮑率候選須每 bit 至少 4 點、最短間距 ≥0.8T、95% 間距相對整數倍誤差 ≤8%，取最低通過值。只填鮑率欄供確認，不自動解碼；雙 bit 脈寬可能使週期為兩倍、鮑率一半；1000000 與 921600 落於 8% 容差重疊區，依最低通過值規則回 921600。

### 5.2 狀態機（`web/uart_decode.py`）
照研究 UART §3.3（`docs/研究_解碼_UART_RS232_RS485.md:96-142`）的虛擬碼實作，下列規則逐條寫進程式與驗收：
- **取樣**：位元中心 `t0+(k+0.5)T` 用 `logic.levels_at(line, t, t1)` 查遲滯後狀態，**不做視窗多數決**（研究 §3.2 的工程簡化）；X 只來自 NaN／檔頭未定／超過 `t1`。每位元 <8 個取樣點 → `warnings`「取樣不足」。資料 LSB first，在本檔組 value（不用 `i3c_fields.field()`）。
- `invert` 只翻轉邊沿值（0↔1，−1 不變），不改門檻。
- **mark 證據 `last_rise`**：擷取起點為 1 → 以擷取起點為初值；每個上升緣（含 X→1 恢復）更新；**進入 X 時清成 None**（X 段不算連續 mark）。擷取起點為 0 → 起點到第一個上升緣輸出 `unsynced` 段。
- **字元區間**：除 false start（見下，中點檢查就失敗、不消耗區間）外，每個進入完整取樣的 start 候選（輸出字元、unsynced 或 BREAK）都消耗 `[t0, frame_end]`，`frame_end`＝最後一個 stop 中心；區間內的下降緣不判 start（stop 起點後、第一 stop 中心前的下降緣記 `short_stop`）。
- **HUNT**：下降緣且 `last_rise` 非 None 且 `t − last_rise ≥ T` 才是候選。候選 start 中點不是明確 0 → **false start**：不消耗區間、不出字元，`last_rise=None`（須重新出現上升緣＋≥T mark），計入 warnings「false start N 次」。候選完整取樣後 stop 無效（含 X）且非 BREAK → 只輸出 `unsynced`（併入 unsynced frame，不出字元）、消耗整個區間、`last_rise=None`、留在 HUNT。stop 有效 → 輸出字元、轉 SYNCED。
- **SYNCED**：前一字元最後 stop 中心之後的任一下降緣即 start（不要求 mark，容許時脈誤差，研究 U20）。輸出的字元 stop 無效 → `framing`、轉 HUNT、`last_rise=None`。
- parity E／O 驗算、M／S 固定值；stop 全部須為 1（S=2 嚴格）。
- **BREAK**：資料全 0、第一 stop 為 0、低電平 ≥ `(1+D+P+S)·T` → `break` 事件（不是 0x00、不另報 framing）、`frame_end`＝低電平結束、進 BREAK_WAIT；BREAK_WAIT 只等上升緣，之後回 **HUNT**（下一個 start 需 ≥T mark，研究 U28）。擷取結束時仍在低：已達門檻 → `break`＋`truncated`，未達 → `truncated`。最後字元未完成 → `truncated`。
- 多數字元 framing 且閒置為低 → `warnings`「可能需切換反相」（研究 POLARITY_SUSPECT，只提示）。
- **分組成 frame**：同一線相鄰字元間閒置 ≤ `GROUP_GAP=2` 字元時間者併成一組（具名常數，不做參數）；兩線的組在時間上重疊時併成同一 frame（取聯集區間），保證 frames 依 t0 排序且不重疊。

### 5.3 frame／field 對應
- frame：`kind='chars'`（一組字元，可含兩線）或 `'unsynced'`；`label`＝前若干字元的 ASCII 預覽。
- field：每字元一個，`kind`＝所屬線 `tx`／`rx`；`t0`＝第一資料位中心、`t1`＝parity 中心（無 parity 為最後資料位中心）；`nbits`＝D（有 parity 為 D+1）；`value`＝資料；`ninth`＝parity 位、`ninth_kind='parity'`（無 parity 為 null）；framing／parity 錯 → `ok=false`，label `FE`／`PE`；BREAK 為 `value=null`、label `BREAK`。
- bits：只存**主線 TX** 的資料＋parity 位取樣（數量＝nbits，與 I3C 一致，時間嚴格遞增）；RX 不存 bits（兩線同時刻取樣無法以無線別的 `DecodeBits` 表達）。雙線時本來就只到字元，不受影響。
- 固定電位合法：RX 整段閒置（手動門檻）照常解，RX 無字元。
- 標註列：只有 TX → 單 lane（逐 bit 顯示資料位與 `P✓／P✗`）；TX＋RX → 雙 lane（上 TX、下 RX，只到字元）。
- 列舉：
  - `DecodeFrame.kind.uart`：`chars unsynced`
  - `DecodeField.kind.uart`：`tx rx`
  - `DecodeFrame.reasons.uart`：`framing parity short_stop break truncated unsynced unknown_bit`（`break`、`unsynced` 不升 error：break 為 ok、unsynced 為 warn）
- 前端 `decode_uart.js`：columns＝字元數；content＝`TX 48 65 6C 6C 6F "Hello"／RX …`；fieldText＝hex（D≤8 兩位，D=9 三位）；summary（取自 options 快照）＝`UART 115200 8N1`（反相時加「反相」）。

### 5.4 合成器與測試向量（`web/uart_synth.py`、`web/uart_check.py`）
- 符號層：`uart_line(chars, baud, bits, parity, stop, eps=0, gaps, idle_level, breaks)` → 單線轉換與真值；`synth.render(levels=…)` 產 TTL 0／3.3 V、RS-232 +12／−12 V、差動 ±1.2 V。`fixture(path)`：TX＋RX 兩通道（U01、U02、U04、U05、U17）。
- 手寫真值：H1＝研究 UART U01（9600 8N1 0x55）逐轉換手寫。
- 向量（研究 UART §10.2）：U01–U13、U14（反相錯 → framing＋反相提示）、U15、U17（兩線獨立、frame 聯集不重疊）、U20、U21、U22（只判第一字元）、U27、U28、U29、U32（U07a／U07b／U10／U28 即驗 mark 起點、擷取起點為低的 unsynced、S=2 嚴格與 BREAK 後重新要求 mark）；另加：NaN 落在資料位 → `unknown_bit`、`value=null`；**X 清除 mark**（NaN 段後立即下降、恢復後 mark <T → 不接受 start；mark ≥T 後的字元正確）；**false start**（idle 中 0.3T 低脈衝後接正常字元 → 無假字元、該字元在 ≥T mark 後正確解出）；**HUNT 無效候選**（擷取起點落在 0x00 字元資料中段、首候選 stop 無效 → 只出 `unsynced`，不從其資料邊沿重複產生假字元）；RX 整段閒置（手動門檻）可解；縮小 `max_edges`（截止點後無字元）；分組（字元間 1 vs 3 字元時間閒置）；雜訊；上限；效能 10M 點×2 ≤15 s。
- 不做：U16、U31（遲滯保持前態，不產生 X）、U18／U19（自動偵測）、U23–U26（Modbus）、U30（DE）。
- `--mutations`：同位 E／O 對調（U02／U03 必紅）、取樣點改 `t0+kT`（U01 必紅）、SYNCED 也要求 mark ≥ T（U20 必紅）、資料改 MSB first（U02 必紅）、進入 X 不清 `last_rise`（X 清除 mark 向量必紅）。

### 5.5 明確不做
自動格式、自動套用鮑率（已做：手動觸發的估計按鈕；解碼本身仍須明確鮑率）、Modbus RTU（3.5 字元分框、CRC-16）、RS-485 DE／RE 通道、衝突判定、半雙工回音、A−B 兩探棒相減（§12 Q4）、1.5 stop、寬鬆 stop、9-bit 位址旗標語意、視窗多數決、glitch 濾波（g_min）、TIMING_MARGIN 統計。

## 6. CAN（Classical CAN 2.0A／B）

### 6.1 通道與參數
- 角色：`can`（必填：CANH、RXD 或差動探棒）、`canl`（可省；有則邏輯線＝`can − canl`）；邏輯線只有 `can` 一條（`DIFF={'canl': 'can'}`），門檻只有一組；BASE＝`can`。
- 參數（預設）：`bitrate`（必填，bit/s，datalist 125k／250k／500k／1M；預設 500000）；`sample_point` 50–95%（75）；`dominant_high`：「高電壓＝顯性（CANH、CANH−CANL、差動探棒）」／「低電壓＝顯性（RXD、CANL）」（高）。
- 自動門檻在差動 0／2 V 時約 0.8／1.2 V（研究 CAN §1 建議 0.5／0.9 V，可手動）。

### 6.2 狀態機（`web/can_decode.py`；必要時拆 `can_fields.py`，各 ≤300 行）
- **尋框（SOF）分兩種情況**：
  - **初始 HUNT**（擷取開頭、錯誤後、`fd` 跳過後、X 段後）：需先看到連續 ≥11 個 recessive 位元時間（bus idle），之後第一個 recessive→dominant 邊沿才是 SOF。擷取開頭就在 frame 中間 → 到 idle 前的活動輸出 `partial`。
  - **已完成訊框後**（EOF 7 位已取完，含「EOF 最後一位 dominant」只標不判的情況）：直接進 intermission，**不要求 11 位 idle**——intermission 第 1、2 位為 dominant → 旗標（見下）；第 3 位或之後的 recessive→dominant 邊沿即下一筆 SOF（研究 CAN §3.5）。這樣 EOF 末位 dominant＋3 位 intermission 緊接下一框不會漏框。
- **位元取樣（工程近似，非 CAN 的 SJW 重同步）**：第 k 位取樣於 `t_sync+(k+sp)·T`。**雜訊判定只有一條規則（向後確認）**：recessive→dominant 邊沿之後的 dominant 位準持續到下一個邊沿 ≥ 0.5 T（下一邊沿超過 `t1` 視為持續）才算有效；邊沿之前的位準持續多久不看。有效邊沿才重新對齊：位元索引 `k = round((t_edge − t_sync)/T)` 不變（不重新編號），相位誤差 `e = (t_edge − t_sync)/T − k`，之後 `t_sync += e·T`（等於無 SJW 上限的重同步）；`|e| > 0.25` → `timing` warn（不改判資料）。無效邊沿（<0.5 T 就翻回）視為雜訊，**不**重新對齊、也不能當 SOF（其位元值仍由取樣點決定）。HANDOFF 與規格文件明寫「無 SJW 限制的逐邊沿重對齊，屬離線工程近似」。
- 值用 `logic.levels_at(can, t, t1)`；`dominant_high` 決定 0／1 對應；−1 → X（`unknown_bit`，該 frame CRC 不驗，回初始 HUNT）。超過 `t1` 的位元不取，frame 標 `truncated`。
- **去填充**（研究 CAN §4.2 的 DYN／TAIL）：線上位元 run 計數含填充位；連續 5 個相同後下一位必須相反，否則 `stuff` error；填充位從欄位位元流移除，bits 中標值 2。
- **欄位**：SOF、ID[10:0]、RTR／SRR、IDE；IDE=1 → ID-B[17:0]、RTR、r1、r0；IDE=0 → r0；DLC；DATA（0–8 byte；DLC 9–15 → 8 byte，保留原值）；CRC-15（poly 0x4599、初值 0、去填充後 SOF..DATA）；CRC delimiter、ACK slot、ACK delimiter、EOF 7 位。remote frame 無資料段。
- **FDF**：基本格式 r0 位置（或擴充格式 r1）為 recessive → kind `fd`、`fd_unsupported`，回初始 HUNT（等 11 位 idle）再找 SOF（§12 Q1）。
- **框內錯誤路徑**（frame 都在「偵測到錯誤的那一位」的起點結束，`t1` 不回溯，之後的位元不屬於該 frame）：
  - 去填充區第 6 個相同位 → `stuff` error；
  - CRC delimiter 之後比對不符 → `crc` error（依規格，CRC 錯誤的旗標在 ACK delimiter 之後才開始，frame 照常取到 ACK delimiter 再結束）；
  - CRC delimiter／ACK delimiter／EOF 第 1–6 位為 dominant → `form` error（EOF 第 7 位 dominant 只標不判，研究 CAN E4 註）；
  - ACK slot recessive → `no_ack` **warn**（單節點錄製不可斷言錯誤；frame 照常結束）。
- **旗標偵測**（錯誤與過載不區分，§12 Q11）：
  - 框內錯誤後：從錯誤 frame 的 `t1` 起掃描，連續 dominant ≥6 位 → 一筆 `error_flag` frame，`t0`＝該 dominant 段第一位起點（必 ≥ 前 frame `t1`，保證不重疊），`t1`＝其後 8 個連續 recessive（delimiter）結束；不足 6 位的 dominant 不成旗標，只回初始 HUNT。
  - **框外 dominant run 偵測（獨立入口，不依賴 SOF 或 11 位 idle）**：凡不在 frame 內（初始 HUNT、旗標 delimiter 後、intermission、擷取起點），以 dominant 段的實際時長量測：連續 dominant ≥ 6 T → 直接成 `error_flag`（無前綴旗標，研究 CAN T11），不當 data frame（避免報成一筆 stuff error 的假框）；<6 T 的 dominant 段不成旗標，照原規則處理（滿足 SOF 條件才開框，否則併入 `partial`）。`t0`＝dominant 段起點，但不早於前一筆 frame 的 `t1`（保證不重疊）；**擷取起點即在 dominant 段中**時 `t0`＝擷取起點、加 `truncated`（起點前長度未知）。`t1`＝其後 8 T 連續 recessive 結束（不足 8 T 就被打斷時，`t1`＝打斷處、加 `form`）。偵測結果與 SOF 判定互斥：先量 dominant 段長度，≥6 T 走旗標、否則才看是否為 SOF。
  - intermission 第 1、2 位 dominant → `error_flag`（過載情況，研究 CAN T12）。
  - 旗標之後一律回初始 HUNT（delimiter 8 位＋intermission 3 位＝11 位 recessive 才找 SOF）；旗標中途擷取結束 → `truncated`。
- 擷取在 EOF 前結束 → `truncated`，CRC 未收齊不驗（不報 `crc`）。
- 每位元 <8 個取樣點 → `warnings`「取樣不足」。

### 6.3 frame／field 對應
- frame：`kind`、`addr`＝ID（11 或 29 bit）、`ack`＝ACK slot 是否 dominant、`label`＝`STD 0x123 DLC 2`／`EXT 0x1ABCDEF`、`rw／start／ccc` 為 null。
- field：`id`（nbits 11／29）、`ctrl`（RTR／SRR／IDE／r 位原始值，label 列名稱）、`dlc`（4）、`data`（每 byte 一個，8 bit）、`crc`（15，`ok`＝比對結果，label `calc 0x…`）、`ack`（1）、`eof`（7）；`ninth_kind` 一律 null。value 在本檔由去填充後的位元算（不用 `i3c_fields.field()`）。field 時間窗內含填充位（bits 值 2，標註列顯示 `S`），所以 CAN 的 `nbits` 不等於窗內 bit 數——CAN 自檢不套用 I3C 的這條斷言。`ack` 是單取樣欄位（`t0=t1`），靠第 0 步的單取樣顯示規則（§2.5）才看得到；fieldText＝`ACK`／`NO ACK`。
- 列舉：
  - `DecodeFrame.kind.can`：`data remote error_flag fd partial`
  - `DecodeField.kind.can`：`id ctrl dlc data crc ack eof`
  - `DecodeFrame.reasons.can`：`stuff crc form no_ack timing truncated error_flag fd_unsupported unknown_bit`
- 前端 `decode_can.js`：columns＝ID（STD 三位／EXT 八位 hex）、DLC；content＝data hex＋`CRC✓／CRC✗`；單 lane；summary（取自 options 快照）＝`CAN 500 kbit/s · 取樣點 75%`。

### 6.4 合成器與測試向量（`web/can_synth.py`、`web/can_check.py`）
- 符號層：`can_frame(id, data, ext=False, rtr=False, dlc=None, ack=True, crc=None, stuff_break=None)` → 線上位元（自算 CRC 與填充；可強制錯 CRC／破壞填充）；`can_bus(frames, bitrate, gaps, slow=0)` → 轉換；`synth.render` 產單線差動 0／2 V，或 `canh`／`canl` 兩線 2.5↔3.5／2.5↔1.5 V（可加共模偏移）。`fixture(path)`：CANH＋CANL 兩通道（T01、T04、T05、T06）。
- 手寫真值（不經合成器）：H1＝研究 CAN §11.1 的 51 位 stuffed 字串（T01，CRC 0x36B7）；H2＝§11.4 T05（CRC 0xD9、4 個填充位）；CRC 檢查值 `"123456789"→0x059E`。
- 向量（研究 CAN §10）：T01、T02、T03、T04、T05、T06（CRC 0x4352）、T07、T11、T13（每位 4 點 → 警告、結果仍正確）、T14、T15（CANH／CANL 各 +2 V，結果同無偏移）、T16（慢 1%）、T17（慢 5% → `timing`、資料仍正確）、T18、T19、T12（intermission dominant → `error_flag`）、FDF=1 frame → `fd`＋idle 後一筆 Classical 照常解；另加：**EOF 第 7 位 dominant＋3 位 intermission＋下一框**（兩框都解出、下一框不漏）；**CRC 錯誤後旗標**（`crc` frame 結束於 ACK delimiter、`error_flag` 緊接且不重疊）；**stuff error 後旗標**（T02 延伸）；**form error 後旗標**；dominant 只 4 位（不成旗標、回 HUNT）；**擷取起點就是旗標**（擷取第一點即 dominant、6 T dominant＋8 T recessive＋3 T intermission＋一筆正常框 → 第一筆 `error_flag`（`t0`＝擷取起點、含 `truncated`）、第二筆 data frame 正確解出、兩筆不重疊；研究 CAN T11 位於 `docs/研究_解碼_CAN.md:471`）；**idle 不足 11 位時的無前綴旗標**（3 T recessive 後 6 T dominant → `error_flag`，不是 `partial`）；雜訊尖峰（<0.5 T 的 r→d 邊沿不重新對齊、資料正確）；縮小 `max_edges`（截止點後無位元）；ACK 欄位在標註列可見（第 0 步規則）；雜訊、上限、效能 10M 點×2 ≤15 s。所有向量另斷言 frames 不重疊。
- 不做：T08–T10（FD）。
- `--mutations`：填充門檻 5→6（T01 必紅）、CRC 多項式改一位（T01 必紅）、拿掉重新對齊（T16 必紅）、DLC>8 不截 8（T07 必紅）、框尾後也要求 11 位 idle（EOF 末位 dominant 向量必紅）。

### 6.5 明確不做
CAN FD 解碼（§12 Q1）、CAN XL、overload 與 error flag 的區分、error passive 旗標、受 SJW 限制的重同步與 SJW／TQ 反推、位元率自動偵測、共模報告、DBC 解析、節點／仲裁歸屬。

## 7. 並行策略

### 7.1 階段與順序
```
S0 第 0 步（main，序列）── 預覽核可（§8）之後才開始
 ├─ 波 1：I2C-A ∥ UART-A（兩個 worktree 同時，Codex）
 │        → 合併 I2C（A＋B）→ 完整驗證 → 合併 UART（A＋B）→ 完整驗證
 └─ 波 2：SPI-A ∥ CAN-A（可在波 1 的 B 階段期間就開始）
          → 合併 SPI → 完整驗證 → 合併 CAN → 完整驗證
```
理由：I2C 沿用 I3C 最多，最快驗證註冊表；UART 先驗雙 lane 與反相；SPI 再用雙 lane；CAN 規則最多、研究待確認項最多，放最後。

- **A：核心＋自檢**（純後端，無 UI）：`<p>_decode.py`（可拆 `<p>_fields.py`）、`<p>_synth.py`（含 `fixture()`）、`<p>_check.py`、`離線分析功能規格.md` 自己那節。可完全並行。
- **B：接線＋UI／瀏覽器驗證**：`decode_<p>.js`（含 `sample`）＋`decode_protocols.js` 一行。同一 worktree 接著做；**合併到 main 一次一個**，每合併一個跑 §9 全部驗證。

### 7.2 worktree 規則
- 分支 `decode-i2c`／`decode-uart`／`decode-spi`／`decode-can`，皆從**第 0 步完成後的 main** 開。
- 變更一律相對 **S0 基點**（§0-D 記下的 commit）檢查，不相對浮動的 main：`git diff --stat <S0>...HEAD` 只能出現 §7.3 自己的新檔、`decode_protocols.js`、`docs/離線分析功能規格.md`。
- **共享檔逐檔核對**：`git diff <S0>...HEAD -- scope_tool/web/static/js/analysis/decode_protocols.js` 必須恰為「+1 行、−0 行」且是自己的 `export … from './decode_<p>.js'`；規格文件的 diff hunk 只能落在自己那節標題與下一節標題之間。不符 → 退回。
- 合併衝突只可能在這兩個檔，lead 保留兩邊；**每次解完衝突都重跑 §9.3 全套**，不沿用衝突前的結果。
- Codex 沙盒不能 bind localhost：Codex 只跑模組自檢與 `selfcheck_node.js`；`e2e_check`、`browser_check` 由 lead 在沙盒外跑。

## 10. 風險

| 風險 | 處置 |
|---|---|
| 只有合成波形，產生器與解碼器可能同樣誤解規格 | 每協定至少一組不經合成器的手寫真值（研究文件的位元串、CRC 值）；HANDOFF／真機清單標「未經實測」 |
