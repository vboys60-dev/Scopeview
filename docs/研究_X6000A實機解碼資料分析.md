# X6000A 實機解碼資料分析與派工規格

資料位置：`X6000A-解碼/{I2C,RS-232,CAN}/`（2026-10-27 於 DSO-X 6004A，MY61410139，韌體 07.40.2021031202 擷取；示波器為停止狀態，視窗＝螢幕）。
每組四檔：`.png` 截圖、`.bin`、`.h5`、`.csv`（示波器序列表匯出＝**解碼真值**）。

| 組 | 檔案 | 設定 | 視窗／H5 取樣間隔 |
|---|---|---|---|
| I2C | `x6000i2c.png` `x6000i2c1.bin` `x6000i2c2.h5` `x6000i2c3.csv` | SDA=CH1（閾值 1.29 V）、SCL=CH3（閾值 1.00 V） | 100 ms／1.55 µs |
| UART | `x6000rs232.png` `x6000rs233.bin` `x6000rs234.h5` `x6000rs235.csv` | Rx=CH3、Tx=CH1，閾值同上 | 100 ms／1.55 µs |
| CAN | `x6000can.png` `.bin` `.h5` `.csv` | CH3（標籤 `CAN_L-H1`） | 500 ms／7.75 µs |

檔名編號不連續為使用者命名所致，不代表缺檔。

## 1. 檔案格式

### H5（與既有讀取器相同）
`/Waveforms/Channel N/Channel N Data`，`float32`，**固定 64516 點**。群組屬性：`XOrg XInc XDispOrigin XDispRange YOrg YInc NumPoints XUnits YUnits WaveformType(3)` 等。**無通道標籤**，不知道哪條是 SDA／SCL／TX／RX。

### BIN（Keysight `AG10`，little-endian）
```
檔頭 12 B：'A''G' + 版本 '10' | int32 檔案總大小 | int32 波形數
每個波形：
  波形標頭（hs=140 B）：int32 hs | int32 type | int32 nBuffers | int32 points | int32 count
    | f32 XDispRange | f64 XDispOrigin | f64 XInc | f64 XOrigin | int32 XUnits | int32 YUnits
    | char[16] date | char[16] time | char[24] frame | char[16] 通道標籤 | f64 timeTag | int32 segmentIndex
  每個 buffer：int32 dataHdrSize(=12) | int16 bufferType | int16 bytesPerPoint | int32 bufferSize
    | 資料（float32，bufferType 1＝一般）
```
樣本：CAN 檔 7984 B＝12＋(140＋12＋1955×4)；I2C／UART 檔 15956 B＝12＋2×(140＋12＋7820)。標籤：`SDA1/SCL1`、`TX1/RX1`、`CAN_L-H1`。

### BIN 與 H5 的關係（逐點比對）
- BIN 為 **1955 點，等於 H5 每 33 點取 1 點（偏移 0，非峰值偵測）**，電壓差僅 float32 捨入級（≤1.2e-7 V，遠小於 1 LSB＝1.3e-4 V；非逐位元相等，SDA1／TX1 兩條剛好相等）；`XInc_bin = 33 × XInc_h5`。
- BIN 的價值只有**通道標籤**（H5 沒有）；解碼取樣率不足，**不可用 BIN 解碼**。
- 兩種檔案都只是螢幕解析度波形，**不是擷取記憶體全長**。

## 2. 可解碼性（以腳本對 CSV 驗證）

- **I2C：可。** 以 H5 解出的位址（`E2 52 53 C8 C9 E0`）、資料（含 `FF 80`、`BA` 對 `BB`）、缺少確認位元（對應 CSV `X`）、起始時間與 CSV 逐筆相符；時間差約 1 個取樣點（CSV `-400ns`，取樣解出 0）。
- **UART：大致可。** 最短邊緣間隔 51.15 µs＝1 位元，約 19200 baud（理論 52.08 µs）；字元間距 ≈573 µs。CSV 在字元之間夾大量 `Unknown Rx Error`／`Unknown Tx Error`，**成因與判定條件尚未釐清**（見 §4-3）。CSV 第 1 列時間為 `?`＝視窗開頭被截斷的半個字元。
- **CAN：檔案不可解。** 位元率約 50 kbps（20 µs/位元），H5 每位元僅約 2.6 點，BIN 更少；示波器本身用 4 MSa/s 完整記憶體解碼。要做 CAN 須經 SCPI 以 `:WAVeform:POINts:MODE RAW` 取完整記憶體，另案處理。

## 3. CSV 欄位（驗收真值）

| 協定 | 欄位 |
|---|---|
| I2C | `Marked,Time,Serial Bus,Restart,Address,Data,Missing Ack`；位址如 `E2W`／`C9R`（7 位址＋R/W），`Missing Ack` 為 `X` |
| UART | `Marked,Time,Serial Bus,Rx,Tx,Errors`；Rx／Tx 欄各一條，錯誤欄如 `Unknown Rx Error` |
| CAN | `Marked,Time,Serial Bus,ID,Type,DLC,Data,CRC,Errors`；Type 有 `Data`／`RMT`，ID 有 11 位與 29 位（`0296A95D`），`Errors` 有 `Stuff` |

注意：時間只有 4 位有效數字（`-34.46ms`、`671.6us`、`-400.0ns`），**比對時間必須用容差**（取 max(1 取樣間隔, 4 位有效數字的捨入量)），文字欄位則逐字比對。

## 4. 派工

通則：沿用 `docs/多協定解碼計畫.md` 與 `研究_解碼_*.md`；純 numpy、不得新增相依；輸入以 H5 為準；每項附自檢（`__main__` 或 `*_check`），以本資料夾 CSV 為驗收；Codex 背景呼叫要加 `< /dev/null`。

1. **I2C 解碼器（先做）**：輸入 SDA／SCL 兩條波形、各自閾值；輸出事件（起始時間、位址＋R/W、資料位元組、缺少確認、Restart）。驗收＝與 `I2C/x6000i2c3.csv` 全部列相符（時間容差見 §3）。
2. **BIN 讀取器**：輸出結構與 H5 讀取器相同，另帶 `label`；多波形、多 buffer 型別需擋下不支援者並報錯。驗收＝`I2C/x6000i2c1.bin` 與 `I2C/x6000i2c2.h5` 每 33 點相等；可由標籤自動指派 SDA／SCL。使用者要求「H5 無標籤時由使用者指派」的 UI 另列。
3. **UART 解碼器**：**先分析再寫**——對 `RS-232/x6000rs235.csv` 歸納 `Unknown Rx/Tx Error` 的觸發規則（疑為另一條線上的活動被當成字元、或框架判定），寫成研究附錄後再實作。baud 先用自動估計（最短邊緣）並可手動覆蓋。驗收＝Rx／Tx 字元與錯誤列相符，`?` 起始列特例處理。
4. **CAN**：不做，等決定是否走 SCPI 取完整記憶體。

## 5. 開放問題
- UART 錯誤規則（§4-3）。
- H5 無標籤時的通道指派 UI。

## 附錄：UART 錯誤規則

2026-10-27，以 H5 原始 64516 點、CH1=TX（1.29 V）、CH3=RX（1.00 V）逐位取樣，並檢視 x6000rs232.png。以下為實作前的分析結果，不把檔名 RS-232 當作電氣格式證據。

### 波形格式與逐字元位元

XInc=1.5500028125 µs；最短 TX 邊沿間隔 51.1500928125 µs，RX 49.60009 µs（門檻／取樣量化使最短間隔不等於精確位元時間）。重複字元起點相距約 572–575 µs，符合 19200 baud 的 11T=572.916667 µs。物理電壓為約 0–2.5 V，**低電位閒置、高電位 start，須 invert=True**。以 19200 baud、start 後各位元中心取樣，資料為 LSB first。以下字串已反相，依序為 start＋8 data＋第九位＋stop；各次重複交易的完整字元均逐一核對，不只比對 ASCII：

| 線／資料 | 11 位元 | data 的 1 數奇偶 |
|---|---|---|
| RX 4B K | 01101001011 | 偶 |
| RX 65 e | 01010011011 | 偶 |
| RX 79 y | 01001111001 | 奇 |
| RX/TX 73 s | 01100111001 | 奇 |
| RX 69 i | 01001011011 | 偶 |
| RX 67 g | 01110011001 | 奇 |
| RX 68 h | 00001011001 | 奇 |
| RX 74 t | 00010111011 | 偶 |
| TX 4D M | 01011001011 | 偶 |
| TX 53 S | 01100101011 | 偶 |
| TX 4F O | 01111001001 | 奇 |
| TX 23 # | 01100010001 | 奇 |
| TX 31 1（前三次） | 01000110001 | 奇 |
| TX 31 1（27.68ms） | 01000110011 | 奇 |
| RX 52 R（三連續） | 00100101001 | 奇 |

完整可見字元支持 **8O1**；第九位為 odd parity，不是合法的 8N2（多個第一 stop 為 0）。但 27.68ms 的 TX 31 第九位反常為 1，故在 8O1 下是 parity 錯誤；也不能單憑波形斷言發送器設定，9N1 或刻意構造的錯誤 8N2 仍可解釋原始位元。

### CSV 錯誤與時間規則

CSV 行為符合 **19200、8N1、反相** 的接收器：把上述第九位當作第一 stop；第九位=1 時輸出資料，第九位=0 時先輸出一列空白，再輸出 Unknown Rx Error／Unknown Tx Error。因此這份資料的 Unknown 對應我方 **framing**，不是 parity；在真正的 8O1 解碼中，y/s/g/h/R/O/#/前三次 1 的 parity 反而正確。27.68ms 的 31 在 CSV 正常、在 8O1 為 parity 錯誤，是辨別兩種規則的重要反例。截圖也確認空白列與紅底 Unknown 列各自獨立存在。

CSV 一般字元／空白列時間為 **start 中心（實體 start 邊沿＋0.5T）**，不是資料中心或 start 邊沿；錯誤列時間為 **第一 stop 中心（邊沿＋9.5T）**，所以相對空白列晚 9T=468.75 µs。CSV 只有四位有效數字，驗收須依每列文字捨入量處理。

第一列 `?,Rx=65` 是擷取起點前已開始的 e；起點欠缺 start 與部分資料，不能用現存波形獨立重建 65，僅能確認後半波形相容，核心應標 unsynced，不猜其值。最後 49.92ms 空白列為 RX R 的 start，擷取在資料區截斷，沒有後續錯誤列；空白不一律表示已確認 framing。

### 與核心規格的差異及不確定處

計畫要求 HUNT 的 stop 無效候選只輸出 unsynced，與儀器在錯誤後仍逐字元列出的策略不同。核心遵守計畫，不為 CSV 改同步規則。實機驗收以 8O1 重建完整字元，再在驗收器中按第九位重現儀器 8N1 的列與時間；這是有明確物理依據的格式轉譯，不是將 parity 原因碼改名。首列不可獨立驗證的 65、末列不完整字元須明列為邊界例外，不算完整字元成功。示波器設定選單未顯示 baud／parity／stop，8N1 是由所有可見列推得的行為模型，不能宣稱已讀到儀器設定。時間殘差與逐列差異由 uart_real_check 實際印出，不以調整偏移消除差異。

### 實作後逐列驗收結果

`/opt/anaconda3/bin/python3 -B -m scope_tool.web.uart_real_check`：CSV 131 列，重現 130 列有時間列（79 個完整字元＝29 個正常字元列＋50 個錯誤前空白列，另有 50 個錯誤列、1 個尾端截斷空白列）；首列 `?/65` 單列列為不可獨立驗值的邊界例外，僅核對現存後半位元相容性。79 個字元的全部 11 位元另作核對；RX 完整序列為首段 `ysightRRR`、三段 `KeysightRRR`、尾段 `KeysightR`；TX 為四段 `MSOs#1` 與尾段 `MSOs`。

所有 130 列的欄位與時間均符合任務指定容差 `max(2×XInc, 文字捨入半量＋XInc)`，差異清單為空。時間殘差為 −6.052560～+5.082691 µs。若使用未加 XInc 的原嚴格容差 `max(2×XInc, 文字捨入半量)`，以下九列超出（列號不含表頭）：9: −5.062819、15: −5.208799、21: +5.082691、26: −6.052560、45: −5.705636、50: −5.660327、98: −5.874803、122: −5.004252、125: −5.901312 µs；這些列的原嚴格容差均為 5 µs。沒有額外擬合時間偏移。

實機驗收器對第一段做了明確的邊界恢復：在第一個字元時間內找首個 odd parity 與 stop 皆正確的實際候選，從其前一個真實 mark 邊沿開始交給核心。這不使用 CSV 字元選相位；未恢復的核心會在半字元資料內假同步，這是研究 §3.3 已列出的限制。驗收器不代表產品新增自動格式／鮑率功能。

合成向量 U04／U09／U10／U21／U22／U27 的 framing 檢查使用一個正確字元作為 SYNCED 前綴，解決研究單字元期望與計畫 HUNT 規則的衝突；另驗原始 HUNT stop 無效時只輸出 unsynced。fixture 的 U01／U02 使用不同原生格式，回傳 sections 指明各段裁切區間與參數，不能以單一 parity 設定宣稱全部通過。核心／符號／檢查只用 numpy 與標準庫；實機驗收讀取 H5 沿用 I2C 驗收已使用、RULES 已允許的既有 h5py，沒有新增套件。
