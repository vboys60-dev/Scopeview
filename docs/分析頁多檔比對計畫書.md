## 2. 現況重點（讀碼結論）

- `analysis_api.py` **已 298 行**（上限 300）。新方法不能塞進去，要開新 mixin 檔。
- `_n_raw`：用「`_waves` 前 N 個」判斷原始通道（`_raw_names()`、`remove_channel` 的 `names.index(name) < self._n_raw`、`analysis_export.py:21` 的 `waves[:self._n_raw]`）。比對檔通道會排在數學通道 F1 之後，這個假設就破了 → 改成名稱集合。
- `cursor_readout` 吸附 `waves[0]`（＝主檔第一通道）；其他通道各自扣 dx、超出時間軸回 `null`。比對檔通道自然可讀，不用改。
- 量測：每通道各自 `_cut`（扣自己的 dx），雙來源 `measure2` 也各自加 dx → **跨檔延遲／相位直接可用**。
- 解碼：`analysis_decode.decode` 用 `logic.validate_time` 要求所有角色通道時間軸 `array_equal`，跨檔（不同軸）自然回 `BAD_REQUEST`「兩通道時間軸不一致」。
- FFT：後端只留一份 `_spec`（`{"id","gen","freq","mag"}`，沒記來源）。
- 數學二元：`mathfn._overlap` 以**來源時間**內插 B 到 A，不看 dx；`math` RPC 沒有 dx 參數。
- **前端把 `file` 變動當換檔**：`measure.js:67` 清量測、`cursors.js:156` 清游標、`gestures.js:108` 清縮放歷史、`fft_markers.js:94`／`marker_layer.js:32`／`fft_marker_layer.js:39` 重設、`mainplot.js:129`／`overview.js:72` 清快取。所以槽位不能寫 `file`（E9）。
  - 附帶發現：既有 `toolbar.js:80` 數學通道也是同 gen 改寫 `file`，加數學通道時量測會被清、游標會重設。這是**既有行為，本案不修**（§9）。
- **只看 gen 或名稱、看不出同名換檔的地方**：`fft_runner.js:45` 簽章＝`[gen, rangeMode, x1, x2, dx]`；`measure.js:65` `sigOf`＝`[range, dx, threshold, 名稱]`；`decode.js:55` 只在 gen 變時清解碼；`mainplot.js:36` `waveKey` 含名稱與 gen、`overview.js` 快取以名稱為鍵。
- **依 `file.channels` 找通道的地方**：`mainplot.js:32` `fetchTargets`（不在 `file.channels` 的通道不抓波形）、`overview.js:5` `fullRange`、`gestures.js:34` 最小取樣間隔。
- `toolbar.js` 的 `modal()` 未匯出；`exportReport(ctx, root, modal)` 已有「把 modal 當參數傳」的前例，新檔照做，避免循環 import。

## 3. 契約變動明細（L0，lead 改；version 維持 2）


### 3.2 新型別

```
SlotSummary = {"slot": "str", "path": "str", "gen": "int", "info": "[str,str][]", "all": "str[]", "channels": "ChannelInfo[]"}
```

- `info` 與 `FileSummary.info` 同格式（檔名、機型、通道、點數、取樣間隔…），供「檔案資訊」逐槽顯示。
- `all`：檔案裡**全部**通道的原名（含沒勾的），前端存起來，重開對話框才能還原勾選框。
- `channels[].name` 為改名後名稱；`derived=false`。

### 3.3 錯誤

| 情況 | code |
|---|---|
| 槽名不是 `Mem1`～`Mem4`、`channels` 含檔案裡沒有的通道、改名後與現有通道撞名 | `BAD_REQUEST` |
| 沒開主檔、讀檔失敗、檔內沒波形 | `SCOPE_ERROR` |
| 讀檔期間主檔被換／關（gen 變了） | `STALE` |

### 3.4 舊行為的說明文字更新（不改簽章）

- `remove_channel`：「只能刪除衍生通道」維持；比對檔通道算原始通道，要用 `remove_slot`。
- `export_csv`：只匯出主檔通道（比對檔與衍生通道都不含）。
- `close_waveform`／`open_waveform`：一併清空槽位。
- §6 store 契約加兩個鍵（`store.js` 本身不改，初值缺＝`[]`／`0`）：
  - `slots`：`[{slot, path, info, all:[原名], channels:[改名後名稱], infos:ChannelInfo[]}]`，唯一寫入者 L5 `slots.js`；開檔／關檔時由寫 `file` 的一方一併設 `[]`。
  - `dataRev`：整數，槽位任何變動 +1；唯一寫入者 L5 `slots.js`。監聽者用它判斷「同 gen 下資料變了」。
- `l0_sem.mjs` 補語義測試；`mock_backend.js` 同步兩方法。

**同一筆 commit 必須含**：契約兩檔、`mock_backend.js`、`l0_sem.mjs`、Analysis 實作。少一個 `contract_check`（`api.py`）或 `l0_check`／`selfcheck_node` 就會失敗。

**自檢要斷言（`analysis_slots` 的 `__main__`）**
- 開主檔 → 加 Mem1（全部）→ 名稱 `Mem1.CHAN1…`、`derived=false`、gen 不變、`all` 為全部原名。
- 加 Mem1 子集 → 只剩勾的、`all` 仍為全部；未勾的 `/wave` 回通道不存在。
- 同槽換另一檔 → 舊通道消失、新通道在、電壓是新檔的。
- `remove_channel("Mem1.CHAN1")` → ScopeError；先 math 建 F1 再加 Mem2，`remove_channel("F1")` 仍可（`_n_raw` 回歸測試）。
- `export_csv` 只含主檔欄。
- 跨檔雙來源 `延遲`（兩檔同波形、Mem1 dx 抵銷人為位移）≈ 0。
- 跨檔 `decode` → BAD_REQUEST「時間軸不一致」。
- 失效：量測含 Mem1 通道後換 Mem1 → 舊 revision `export_measurements` STALE；只量主檔通道時換 Mem1 → 仍可匯出。FFT 來源為 Mem1 通道時換槽 → `fft_track_rf` STALE；來源為主檔則不受影響。Mem1 通道解碼後換槽 → `decode_frames` STALE。
- `remove_slot` 空槽回 None；`Mem5` → BadRequest。
- 讀檔中換主檔 → StaleError；`close_waveform` 後 `_slots == {}`。

## 8. 風險

| 風險 | 說明／對策 |
|---|---|
| 記憶體 | 主檔 4 通道 × 100M 已約 7 GB；再加 4 槽沒上限。本案不設上限，只在驗收清單記錄；若要設，加在 `add_waveform` 依總點數擋。 |
| 300 行上限 | `analysis_api.py` 298、`analysis_check.py` 286、`mock_backend.js` 263。新邏輯一律進新檔；`analysis_api.py` 靠搬出 `_file_rows` 抵銷；超過就停下回報。 |
| 改勾選要重讀檔 | E2 的子集套用會再讀一次檔，大檔等兩次。`ponytail:` 註記；要改再讓後端暫存該槽完整清單。 |
| 漏掉某個「看 file 找通道」的地方 | E9 不寫 `file`，靠 §2 列出的 `fetchTargets`／`fullRange`／`gestures.js:34` 盤點。之後新功能若只看 `file.channels` 會看不到比對檔通道。`l4_check` 斷言 `fetchTargets` 含槽位；`browser_slot_checks` 實際看主圖有抓。 |
| `dataRev` 變動造成全部重抓／重算 | 任何槽位變動都清主圖與概觀快取、重算量測與 FFT（即使只動到 Mem2、量測只用主檔）。簡單優先；慢了再改成只清受影響名稱。 |
| `remove_slot` 無世代參數 | 前端在呼叫前後核對 `file.gen`；若「舊 `remove_slot` 送出 → 開新主檔 → 新檔已加同名槽」在毫秒內交錯，後端可能刪到新槽。同步 RPC 依序處理、實務上不會發生；要根除得加 gen 參數（改契約）。 |
| 解碼過期由 `slots.js` 代標 | `decodeResult` 平常由 `decode.js` 寫，本案 `slots.js` 照 `decode.js:51` 同一寫法代標 `stale`，避免動凍結檔。後端 STALE 是第二道保險。 |
| 通道列擠 | 4 槽 × 4 通道＋主檔＝最多 20 欄，HANDOFF 已知「通道多時右側被橫向捲動切掉且無提示」。本案不處理（D5：通道列不動）。 |
| 顏色／形狀重複 | 6 色、4 形狀循環，通道多時會撞。名稱前綴 `Mem1.` 可分辨；不另處理。 |
| 已在用的通道被移除 | 量測列回「來源通道已刪除」、FFT 來源消失、解碼標過期。衍生通道 F 不跟著刪（後端不記來源）。 |
| 只有 headless 驗證 | 沒真人手感、沒 WKWebView 實測；pywebview 原生選檔對話框在對話框內再開一次的行為未驗。 |
