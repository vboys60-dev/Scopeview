## 2. 跨協定共通前提：門檻、取樣率與可觀測性

電氣規格中的 `VIL(max)`／`VIH(min)` 是保證辨識區，不是接收器實際翻轉電壓，更不是離線解碼唯一正確門檻。單端 CMOS 可先估高低平台，以中點作候選，再由使用者覆寫；實作使用兩個門檻 `V↓ < V↑`，電壓落在兩者之間時維持前態。開始落在中間區、缺值或擷取中斷時維持 unknown，不能憑空補成 0。合規檢查則另外使用規格門檻及原始類比波形。〔來源：I1 §6、N1 電氣特性、R1 receiver；遲滯與 unknown 政策為實作建議〕

差動輸入優先使用差動探棒，或同步通道計算 `Vdiff = V+ − V−`；兩通道須有共同時間基準及可校正的 deskew。只看 CANH、CANL 或 RS-485 單線也可能解碼，但抗共模能力較差，結果應標「單線近似」。沒有 DE／TXD 等附加訊號時，單靠共用匯流排電壓通常不能判定實際傳送節點、誰輸掉仲裁或是否發生推挽衝突。〔來源：R1、R2、C3；可觀測性限制為研究判斷〕

### 2.1 解碼所需最低取樣率：經驗估計，不是標準保證

以下 `Fs ≥ N × Rbit` 是針對乾淨波形的起步估計；同步協定還要滿足最短 SCL／SCLK 高低脈衝及 SDA 有效窗。建議再要求 `Fs ≥ 4 / Wmin`，讓最短重要脈衝至少有約 4 點；若要量測幾 ns 的建立／保持時間，應再提高取樣率並考慮類比頻寬、探棒與通道偏移。Nyquist 的 2 倍條件不能保證方波邊沿或協定事件可辨識。〔來源：本研究工程估計；不是任何協定的規範最低值〕

| 協定／模式 | 經驗起步值 | 建議範圍／例子及限制 |
|---|---|---|
| I3C SDR | 每位元 ≥10 點，且最短脈衝 ≥4 點 | 12.5 Mbit/s 起步 125 MSa/s，較佳 250–500 MSa/s；3 ns 等級時序宜以 GSa/s 資料檢視 |
| I3C HDR-DDR | 每個邊沿資料位元 ≥10 點 | 25 Mbit/s 起步 250 MSa/s，較佳 500 MSa/s 以上；不可用 12.5 MHz ×10 當 DDR 的完整條件 |
| I3C HDR-TSP／TSL | 每個最短符號／轉換間隔 ≥10 點 | 依符號時序選 Fs；初期可用 500 MSa/s–1 GSa/s 作研究擷取，規範最短間隔待確認；不能以有效 Mbps 直接換算 |
| I3C HDR-BT | 每 lane 的實際 SDR／DDR 位元 ≥10 點 | 單 lane DDR 25 Mbit/s 時起步 250 MSa/s；多 lane 是增加通道數，不是把總吞吐量當單線位元率 |
| I2C | 每 SCL 週期 ≥10 點，另檢查最短高脈衝 | 100 kHz／400 kHz／1 MHz 對應 1／4／10 MSa/s 起步；Hs 3.4 MHz 雖為 34 MSa/s，60 ns 高脈衝若取4點需約67 MSa/s，宜 ≥100 MSa/s |
| SPI | 每 SCLK 週期 ≥10 點，推薦 20–50 點 | 50 MHz：500 MSa/s 起步，1 GSa/s 以上較佳；窄 duty cycle、資料延遲仍可能要求更高 |
| UART／RS-232 | 每位元 ≥8–10 點；推薦 16–32 點 | 115200 baud：1.152 MSa/s 起步；1 Mbaud：10 MSa/s 起步；硬體 UART 的16×過取樣不是離線解碼法定門檻 |
| RS-485 承載 UART | 同 UART，另觀察差動與換向 | 依實際 baud；近零電壓／三態期間不應強行當有效字元 |
| Classical CAN | 每位元 ≥10 點；推薦 20–50 點 | 1 Mbit/s：10 MSa/s 起步、20–50 MSa/s 較佳 |
| CAN FD | 依較快 data phase 每位元 ≥10 點 | 8 Mbit/s：80 MSa/s 起步、160–400 MSa/s 較佳；nominal phase 也要獨立復原 |

表中速率背景取自 M3／T1、I1、S1、U2、R1、C1／C3；所有取樣倍率與建議 Fs 均是本研究估計，不是來源宣告的解碼下限。高取樣率不能補救類比頻寬不足、混疊、錯誤門檻或深記憶體擷取缺段。〔來源：前述各來源；工程判斷〕

### 3.2 實體層與類比判位

基礎匯流排是共地的 SCL、雙向 SDA 兩條單端線，不是差動。SDR 通常由 Active Controller 驅動 SCL；SDA 在可仲裁階段使用開汲極（Open-drain，OD），資料階段多使用推挽（Push-pull，PP）。OD 靠上拉形成高位，PP 主動驅動高低；Controller 可控制動態上拉，另有 high-keeper。一般不是在總線兩端各接 120 Ω 的傳輸線終端。閒置通常 SCL、SDA 都為高；Bus Free／Available／Idle 是不同時間資格，不能只憑一個高電位樣本混為一談。〔來源：M2「Physical／Timing」、T1 pp.6、14、R1 終端對照〕

I3C 常見 I/O 供電實例為 1.2／1.8／3.3 V 等，但允許範圍與耐壓取決於控制器、Target 及所選版規格，不能假定可任意混用。CMOS 判位常以 `≤0.3×VDD`／`≥0.7×VDD` 為保證低／高的參考區；本研究的離線初始門檻建議是平台中點，例如 1.8 V 訊號先試 0.9 V，再設定遲滯。這個中點不是 I3C 的合規門檻；N1 的器件電氣規格、OD VOL、PP VOH／VOL、負載及上升時間須另查。〔來源：N1 I3C DC／AC 特性；中點及遲滯為實作建議；通用完整電壓範圍待確認〕

### 3.3 SDR 訊框與 T-bit

在 SDR 狀態，START 是 SCL 高時 SDA 由高變低，STOP 是 SCL 高時 SDA 由低變高；Repeated START（Sr）是在未 STOP 下重新開始位址階段。一般資料 MSB first，SDA 在 SCL 上升緣前建立並於有效窗保持；解碼依實際 SCL 邊沿，不可假定固定週期。特殊 read turnaround、HDR／Reset pattern 的 SDA 轉換要由狀態機解釋，不能全被通用 I2C START／STOP 偵測器搶走。〔來源：T1 pp.9–12、M2 SDR／Reset；M4 §4.3.2、§4.3.9–10 定位〕

| 階段 | 線上內容 | 解碼意義 |
|---|---|---|
| 位址 header | `A[6:0] + R/W + ACK/NACK` | 7-bit 位址；R/W=0 寫、1 讀；ACK 為低、NACK 為高；保留第9位 ACK，不可全部改叫 T |
| Private write | `S/Sr → DA/W → A → (D[7:0] + Tparity)* → P/Sr` | Controller 送資料；每個資料 byte 的第9位由傳送方送奇同位元 |
| Private read | `S/Sr → DA/R → A → (D[7:0] + Tcontrol)* → P/Sr` | Target 送資料；第9位為繼續／結束交握，不是讀資料 parity |
| 常見開場 | `S → 0x7E/W → A → Sr → DA/R或W ...` | 建立 I3C 管理／傳輸脈絡及可仲裁 header；不是規定每一筆 Private transfer 必須重新送 CCC |
| I2C legacy transfer | `S → static address/RW → A → data + ACK/NACK ...` | 使用 I2C 規則；第9位解釋與 I3C 資料不同 |

上表是核心 SDR 流程摘要，`DA` 為 dynamic address，`A` 為 ACK，`P` 為 STOP；CCC／DAA 另有專用流程。長度不是固定8 bytes，受命令定義、SETMWL／SETMRL 及終止條件控制；SDR 本身沒有每筆必帶 CRC，內容協定可另加校驗。〔來源：T1 pp.9–13、M3 p.18–20、M2 CCC／長度說明〕

**寫入 T-bit**：採奇同位元，`T = 1 XOR D7 XOR ... XOR D0`，使9位 XOR 為1；例如資料0x00時T=1，0x01時T=0。它取代的是 I2C「資料 byte 後接收方 ACK」的位置，不取代 address ACK，也不能使傳送者得知每個 byte 是否已被接收方接受。CCC code／寫資料的 parity 仍需依對應流程檢查。〔來源：T1「Ninth Bit of SDR Controller written data」、P2 SDR error；公式為奇同位元定義展開〕

**讀取 T-bit**：Target 表示繼續時送1並按 turnaround 規則釋放 SDA，Controller 得以拉低提前結束；Target 沒更多資料時送0結束，之後 Controller 產生 Sr／P。因此不能對 private read 或 IBI 資料的第9位做奇同位元檢查；也不能只採一次高／低就斷言結束由誰發起，應保留 T-bit 期間 SDA 轉換及相對 SCL 時序。〔來源：T1 p.12、M2 Q17.14／Q23.24；可觀測性建議〕

### 3.4 OD／PP 切換及 I2C 共存

| 階段 | SDA／驅動處理 | 狀態機應做什麼 |
|---|---|---|
| 閒置、初始 START 與可仲裁 address header | SDA 可被多裝置拉低；OD 保留 wired-AND 仲裁能力 | 接受 IBI／Hot-Join／CRR 競爭，不先認定 START 一定來自 Controller |
| I3C address ACK 後的 SDR payload | 切換為資料傳送方 PP；接收方不在每 byte 送 ACK | 以方向解釋 write parity／read T-control；ACK 到 PP 的交接要留時序窗 |
| 已建立 I3C 脈絡後的 Sr 與不可仲裁 header | 不必因 Sr 一律退回 OD；header 可由 Controller 以 PP 送出，ACK 時仍需釋放給 Target | 分辨 arbitrable／non-arbitrable header；不可寫死「所有 address bits 都是 OD」 |
| Read／IBI T-bit、傳輸結尾 | 會有釋放、high-Z、keeper、Controller 接手 | 保留子階段，不把所有 PP→OD 切換綁在整數 byte 邊界 |
| ENTDAA | PID／BCR／DCR 仲裁及位址指派主要為 OD；Sr+0x7E/R 可為 PP | 使用專用 DAA 子狀態機，不能套一般9位資料字 |
| Legacy I2C transfer | SDA 使用 I2C OD／ACK 規則；SCL 由 I3C Controller 依相容策略驅動 | 維持 I2C profile；不把較慢時脈當成切換協定的充分證據 |

切換點摘要來源為 M2、M3 p.19、T1 p.10、P1。OD／PP 是依協定推論的驅動模式；單看電壓上升快慢，無法可靠證明裝置真的切換了輸出級。〔來源：上述原廠流程；可觀測性為研究判斷〕

I3C mixed bus 主要容納具合適50 ns spike filter 的 I2C Fm／Fm+ Target，不能宣稱任意 I2C 元件可直接共存；legacy clock stretching、I2C 多控制器、沒有所需濾波器的裝置都不能任意沿用。I3C Controller 對 legacy Target 使用相容的 address／ACK／速率；對 I3C 流量則用較短 SCL 高脈衝等方式讓 legacy 裝置忽略。I2C static address 必須避開 dynamic address 指派範圍及 I3C 保留位址。〔來源：M2「Migration／I²C coexistence」、M3 p.21、I1 §3〕

首次送 `0x7E/W` 通常要用較慢 OD 時序，讓仍開著 spike filter 的 I3C 裝置能看見並關閉濾波器；不能看到4 MHz address header就認為整條匯流排一定以該速率初始化。T1 圖例約200 ns低、45 ns高只是特定情境；M2 說明還有2.5 MHz OD及不同濾波條件。解碼器應量出每階段時序，不以單一「I3C baud」硬判。〔來源：M2「Timing Parameters」、T1 p.10；完整版本化 OD 高／低界限待 Basic 原文確認〕

### 3.5 7'h7E、CCC 結構與常用碼

`7'h7E` 是 I3C 管理用廣播位址，不是 Target 的普通 dynamic address；線上含 R/W 的 byte 在寫時是0xFC，在讀時是0xFD，介面應同時保留7-bit address與原始header byte，避免混淆。`0x7E/W` 後直接送 CCC code 才是 CCC 流程；若後面是 Sr+Target address，可能是 Private transfer。`0x7E/R` 在 ENTDAA 脈絡有特殊意義，不能套「廣播讀一定非法」。〔來源：T1 address／CCC、P1 ENTDAA、M2 CCC〕

CCC 的 Broadcast 類對全匯流排設定，通常 `S → 0x7E/W → ACK → CCC+T → [payload+T] → P`；Direct 類先發 `0x7E/W → CCC+T → [Defining Byte+T]`，再用 Sr+Target address及R/W，接各 Target 的資料段，可連續處理多個 Target。CCC bit7通常區分Broadcast（0）／Direct（1），但碼值和可用形式仍查表，不能由OR 0x80自動創造不存在的命令。Defining Byte、Sub-Command、資料長度和回傳欄位隨命令／版本而異，應以命令描述表驅動。〔來源：M2「CCC」、M3 p.20、Z1；M4 §4.3.7 定位〕

|---|---|---|---|
| ENEC／DISEC | 0x00／0x01 | 0x80／0x81 | 事件mask；啟用／停用IBI、Controller Role Request、Hot-Join等，支援項依角色而定 |

| ENTDAA | 0x07 | — | 進入動態位址分配 |
| DEFTGTS（舊稱DEFSLVS） | 0x08 | — | 告知Target清單，供多Controller管理 |

### 3.6 ENTDAA 動態位址分配

1. Controller 送 `S → 0x7E/W → ACK → ENTDAA(0x07)+奇同位元`，再送 `Sr → 0x7E/R`。這個讀header是進入DAA仲裁，不是普通Private read。〔來源：P1、T1 DAA、M2〕
2. 尚未有dynamic address且參與分配的Targets，以OD同步送 `PID[47:0] → BCR[7:0] → DCR[7:0]`，共64 bits、MSB first；這64位中沒有每byte插入一般SDR T-bit。送1卻讀到0的Target退出該輪，最低串接值勝出。PID並非dynamic address。〔來源：P1；[AMD PG439 ENTDAA](https://docs.amd.com/r/en-US/pg439-axi-i3c/ENTDAA)，v1.0〕
3. Controller 送新的7-bit dynamic address及奇同位元，勝出Target在後續ACK位回覆接受；失敗／parity不符可NACK。這是7個address bits的parity，不是8-bit payload parity；其後仍有ACK，不能把9位地址階段錯排成普通資料字。〔來源：P1；AMD PG439 ENTDAA v1.0〕
4. Controller 重複 `Sr → 0x7E/R`，讓剩餘Targets繼續，無回應時結束。被動解碼器只在分配及ACK可確定時更新 `PID ↔ DA`，保存開始／失效時間；RSTDAA、SETDASA、SETNEWDA、Reset／Hot-Join都可能改變表。中途開始擷取時，未知DA不能捏造PID。〔來源：P1、M3 address管理；表更新為實作建議〕

一般DAA可發現Targets，但帶重複／隨機PID或特定能力的器件需要依其規範處理；只看匯流排，不能列出所有落敗裝置的完整PID，也不能把「無人繼續」一律當作故障NACK。〔來源：P1 仲裁描述、M2 DAA；被動觀測限制〕

### 3.7 IBI、Hot-Join 與仲裁

IBI（In-Band Interrupt）是Target在可發請求的匯流排時段拉低SDA，Controller提供SCL後，Target以dynamic address加R=1進行header仲裁；多Target同時請求時低位址優先。Controller可ACK／NACK；若該Target的BCR表示有payload，ACK後會送Mandatory Data Byte（MDB），再接可選資料，以read T-bit控制結束。無payload能力的IBI不能被硬要求一定有MDB；應結合BCR／先前設定解釋。〔來源：M3 p.24、T1 IBI、M2「IBI」〕

IBI的address／ACK是OD仲裁階段，後續payload有PP及T-bit交接；NACK可能是合法延後服務，應標「IBI rejected／deferred」，不直接等同parity或framing error。IBI enable、SETMRL的IBI最大長度及MDB語義會影響判讀；未看到初始化時顯示「能力未知」。CRR通常以Target的DA加W=0表達角色請求，不應誤標為一般IBI資料。〔來源：M2「IBI／Controller role」、M3；標示政策為實作建議〕

Hot-Join 用於匯流排運作後新加入、尚未取得DA的Target，使用保留7-bit位址 `0x02`、R/W=0請求；Controller ACK後可安排ENTDAA，並非Hot-Join header本身就配完地址。多個新Target可共用同一請求，之後再由DAA區分；亦有使用Repeated START而非STOP後立即ENTDAA等流程。標註需分開「Hot-Join請求／接受／後續DAA」，不要將0x02變成普通Target身分。〔來源：M2 Hot-Join、M3 p.28、O1 Hot-Join搜尋；詳細版本化時序待規範確認〕

### 3.8 HDR 模式：框架、速率與 Basic 邊界

HDR由SDR中的 `ENTHDRn` 進入，之後切換符號／frame解析器。SDR-only Target也必須辨識進入並忽略不支援的HDR資料，直到HDR Exit；不能繼續把HDR波形解成錯誤I2C。各模式一般是先選定Target再傳資料，OD多方逐位競爭不是HDR資料區的仲裁機制。〔來源：M2、P2／P3、M4 §4.3.10定位〕

| 模式 | 線上編碼與訊框概念 | 速率觀念、錯誤檢查、公開範圍 |
|---|---|---|
| SDR | SCL單緣資料；8-bit＋T、address ACK | 單lane raw 12.5 Mbit/s；長payload理想8/9後約11.1 Mbit/s，另扣header；Basic所有上述版本均含 |
| HDR-DDR（ENTHDR0） | SCL雙緣取資料；command／data採16-bit word，帶preamble及兩個parity bits；結尾有CRC word／控制流程 | raw 25 Mbit/s，M3示例effective約20 Mbit/s；CRC-5，不是SDR的每byte T；完整I3C有，Basic自v1.1.1納入單lane選用能力 |
| HDR-TSP（ENTHDR1） | SDA與SCL共同承載ternary轉換符號，不再是「SCL clock＋SDA資料」；binary block映射成symbols | Pure bus，不容納legacy I2C；M3單lane有效約33.33 Mbit/s；不在Basic，完整符號／command／CRC及控制碼表需會員規範 |
| HDR-TSL（ENTHDR2） | 同為ternary，但避開破壞legacy共存的符號序列 | 可用於符合條件的mixed bus；M3有效約23.52 Mbit/s；不在Basic；不能直接拿TSP碼表套用 |
| HDR-BT（ENTHDR3） | Bulk Transport；Header／Indicator／Data／CRC等blocks及flow-control；可用SDR／DDR編碼、多lane；資料以32-bit block組織 | M3示例單／雙／四lane有效約24.24／48.48／96.96 Mbit/s；CRC-16／CRC-32，版本化header及packing重要；Basic自v1.1.1納入相關選用能力 |

模式表來源：M2 HDR、M3 pp.13–15、T1模式介紹。表內effective數字是特定長傳輸的教學比較，非所有長度保證吞吐量；T1與M2個別概觀的raw／effective用語及數值有不同口徑，不能混成單一時序上限。Ternary精確最高raw rate、符號映射及最短transition時間待完整規範確認。〔來源：M2／M3／T1交叉比較；研究判斷〕

HDR-DDR 的CRC Word包含preamble、CRC token（0xC）及CRC-5，官方FAQ說明通常佔6個完整clock；早停／write abort時是否送CRC取決於ENDXFER等能力配置。16-bit資料word的MSB順序、parity覆蓋及CRC初始化／多項式／輸入位序需依所選Basic版逐項核對，本次不把未核對的值列成實作常數。HDR不沿用I2C的逐byte ACK；HDR-DDR可有版本及配置相關ACK/NACK／早停機制。〔來源：M2 Q18.16、Q19.1–9；M4 HDR章節定位；精確CRC參數待確認〕

HDR-BT 的v1.2 Header Control bit[4]=1表示新版framing，包括Broadcast CCC資料放在Data Blocks、零資料傳輸不送CRC Block等改變；舊framing bit[4]=0需要相應舊規則。CRC-16／32的選用條件、lane bit packing、header parity、Transition_Control／Transition_Verify及資料block delay都需要版本profile；不是看出有CRC16就足以完整解碼。Basic雖包含BT，不代表BT可免讀原始規格實作。〔來源：M2 Q19.13–18；M4 §6.4.3定位，完整欄位／CRC參數待確認〕

### 3.9 HDR Exit／Restart、Target Reset patterns

**HDR Exit**：先令SCL低、SDA高；SCL持續低時，SDA有4次高→低轉換（中間有上升，不能只數4個任意邊沿），其後升高SCL並產生正常STOP回SDR。P2的晶片說明要求各SDA transition間隔至少32 ns；新版規範使用 `tDIG_H` 約束各線轉換，適用精確值應依版本原文確認。Exit也用於某些錯誤復原，即使之前未成功解出ENTHDR，也要能辨識候選。〔來源：P2；M2 Timing、M4 §4.3.10.2／§4.3.11.2定位〕

**HDR Restart**：保留HDR模式、分隔多筆HDR message；與Exit後回SDR不同，不能用一般Sr替代。其精確pattern／transition計數與每模式條件本次未從完整規範核對，標「待確認」；實作前查M4 §6.1.1，不應推測為某個任意SDA脈衝數。〔來源：M2 Timing交叉引用、O1 pp.8–9〕

**Target Reset**：SCL低且SDA起始高，送14次SDA轉換（7次下降），再接Repeated START及STOP；Reset action在STOP之後生效。RSTACT可先指定不重設／周邊重設／whole-target reset等；連續pattern的升級及設定清除規則依版本／能力解析，不能一看到14個邊沿就直接聲稱器件已完成全晶片Reset。這不是「送9個SCL脈衝」的I2C bus clear。〔來源：P3 §1.11、M2 Q23.15–20；M4 §4.3.9定位〕

Pattern偵測應先保留整段SCL低期間的SDA轉換，再判斷完整尾段：Target Reset在早期也可能累積到HDR Exit的4次下降，不能提早消耗樣本後漏掉Reset。起始線狀態及SCL／SDA轉換不能同時亂跳；tDIG_H、尾端Sr／STOP及缺失條件均要記錄。未完整擷取標「候選／不完整pattern」，不把缺尾段硬判成成功Reset。〔來源：M2 Timing／Reset；優先判定及標示為實作建議〕

### 3.10 時序、設定、自動偵測及異常

I3C時序應分成OD header、PP SDR write、PP SDR read turnaround、IBI、DAA、HDR及pattern profiles。至少量 `tLOW`、`tHIGH`、`tSU_PP`、`tHD_SDR`、OD setup／hold、START／STOP／Sr間隔、`tSCO` 及bus資格時間；通常取SCL有效緣附近SDA穩定值，另查有效窗，不能採SPI式任意CPHA。N1 Table25有PP setup最小3 ns的器件例；M2指出舊版tSCO最大12 ns，新版放到20 ns，可能需要降低最高讀速率。上述不是「固定12.5 MHz一定能解」的保證；通用hold／OD及全部模式的數值表仍待Basic原文逐項核對。〔來源：N1 Tables24–25、M2 Timing／GETMXDS；M4 §4.3.11定位〕

| PP `tLOW`／`tHIGH` | N1 Table25：類比門檻量測的高低期間各至少24 ns | 與數位有效高低時間不同，不可混稱同一脈寬 |

|---|---|---|
| SCL／SDA通道、每線門檻／遲滯、反相／deskew、glitch策略 | 高低平台、SCL邊沿與局部時脈、START／STOP候選 | 實際VDD／接收器門檻、誰驅動／是否PP衝突 |
| 完整I3C或Basic、版本／errata、pure／mixed、legacy地址清單 | CCC／ENTHDR模式、已捕獲的DAA位址表 | 沒看到GETCAPS／初始化時的全部能力、擷取前地址對應 |
| 啟用SDR／指定HDR、lane mapping、初始模式／地址表（擷取中途） | GETBCR／GETCAPS／GETMXDS／長度設定與版本線索 | 從單筆Private byte斷定I2C或I3C、從時脈斷定版本 |
| HDR版本及CRC profile、符號時序容許值 | 用parity／CRC／pattern一致性排名候選 | 未核對規範的CRC參數、ternary碼表 |

上表是依M2／T1／P1訊號可觀測性提出的實作建議。I3C基本位址為7-bit、SDR為MSB first，使用者不應用任意位序或10-bit位址選項「修正」成非標準I3C；10-bit只適用另行啟用的I2C解析情境。〔來源：T1、I1；參數界面建議〕

| 情況 | 建議標示及處置 |
|---|---|
| 地址NACK／IBI NACK／DAA最後無人回應 | 分別顯示原因脈絡；是協定事件，不一概標壞封包 |
| SDR write T parity不符 | `parity error`，標byte及T-bit時間；保留raw bits |
| SDR read T交接／結束不合法 | `T-bit / turnaround error`；不要誤標parity error |
| 0x7E／DAA地址保留值、位址parity、重複地址 | `address / DAA error`；未見初始化則區分unknown與確定錯誤 |
| HDR parity／CRC／preamble不符 | 各自標示；不支援模式標`unsupported mode`，不是CRC error |
| CCC格式／Defining Byte／長度不符 | `CCC format / length error`，帶版本profile；未知碼保留十六進位 |
| 偵測到Exit／Reset、clock停頓或不完整frame | 顯示事件、截斷／復原點；合法clock stall不可一律timeout error |
| glitch／模糊邊沿、setup／hold不足 | `glitch candidate`／`timing margin limited`；保留濾波前後差異 |

異常類型依M2錯誤處理、P2 TE0–TE5、O1搜尋能力整理；名稱與處置是本研究建議。離線觀察到的錯誤不等於Target內部一定進入對應TE狀態，TE標籤僅能作規範候選解釋。〔來源：M2、P2；研究判斷〕

## 4. I2C

### 4.1 實體層、速率與時序

SDA／SCL為共地單端線，傳統雙向I2C均為OD／open-collector及上拉，閒置皆高；多控制器靠wired-AND仲裁，Target可拉低SCL做clock stretching。常見1.8／3.3／5 V設計不是固定標準供電；一般以VIL≤0.3VDD、VIH≥0.7VDD為電氣參考，離線中點判位要可調。上拉值依電容、上升時間及灌電流決定，不是匯流排兩端120 Ω終端；高阻抗探測避免改變RC。〔來源：I1 §3.1、§6、§7〕

| 模式 | 最高SCL | tLOW最小 | tHIGH最小 | tSU;DAT最小 | 上升時間最大 |
|---|---:|---:|---:|---:|---:|
| Standard | 100 kHz | 4.7 µs | 4.0 µs | 250 ns | 1000 ns |
| Fast | 400 kHz | 1.3 µs | 0.6 µs | 100 ns | 300 ns |
| Fast-mode Plus | 1 MHz | 0.5 µs | 0.26 µs | 50 ns | 120 ns |
| High-speed | 3.4 MHz | 160 ns | 60 ns | 10 ns | 依SCL／SDA與負載條件查表，不能共用單一值 |

來源：I1 §6 Tables11、13；Hs列採其相應低負載條件，高負載另有時序。F/S/Fm+的data hold表列最小可為0，但裝置仍要提供SCL邊沿不確定區的內部保持條件，不能當作邊沿同時跳變就永遠安全。完整START／Sr setup、hold、STOP setup、bus-free皆查I1對應模式表；離線抽值可在SCL上升緣並檢查高期間穩定性，clock stretching按實際邊沿處理。〔來源：I1 §6及表註〕

Hs進入前先用F/S速率傳master code等流程，之後切Hs；不可以整段單一baud硬切。Ultra Fast-mode為單向推挽、可到5 MHz，沒有一般雙向ACK／仲裁，應作獨立可選profile；它不是一般I2C快速版，也不是I3C。取樣率依§2.1，短高脈衝可能比平均SCL週期更先限制解碼。〔來源：I1 §5、§6.2–6.3；取樣率為工程估計〕

### 4.2 訊框、設定與錯誤

一般訊框 `S → A[6:0]+R/W → ACK → (data[7:0]+ACK/NACK)* → P/Sr`，MSB first、每byte8 bits。START／STOP定義同§3.3；資料在SCL高時保持。接收方第9個clock拉低表示ACK，釋放高表示NACK；讀取最後byte由Controller送NACK是正常結束。7-bit地址不包含R/W；General Call等保留用途須額外命名。〔來源：I1 §3.1〕

10-bit地址先送 `11110 A9 A8 W`，ACK後送 `A7...A0`；讀取通常先完成寫方向地址設定，再Sr及 `11110 A9 A8 R`。資料長度無總線固定上限，由裝置／上層決定；I2C本身沒有parity或CRC，SMBus PEC等另屬上層profile。多控制器在送1卻讀0時失去仲裁，這是正常競爭；只有匯流排捕獲不能指出哪個實體節點落敗。〔來源：I1 §3.1仲裁、§3.1.11 10-bit addressing；研究觀測限制〕

必要設定：SCL／SDA、門檻／遲滯、7／10-bit或自動解析、地址顯示7-bit／含R/W byte、速率mode（供時序檢查）、glitch策略；可自動辨識clock、S／Sr／P、R/W、ACK、clock stretching候選及10-bit prefix。寄存器地址長度、endianness、PEC、讀寫命令語意需上層裝置設定，不能從I2C底層保證推知。〔來源：I1、O3 §11.4；設定與自動判讀為實作建議〕

異常應分`address NACK`、`data NACK`、正常`read end NACK`、`missing STOP／truncated`、`SDA/SCL stuck low`、`timing violation`及`glitch candidate`。SCL高期間SDA改變可能是合法S／P或雜訊，需看前後狀態；不能直接報UART式framing error。Clock stretching過長只在使用者指定裝置／SMBus timeout後才能判超時，一般I2C沒有任意統一timeout可套。〔來源：I1 §3、O3；標示政策為實作建議〕

## 5. SPI

### 5.1 實體層與四種模式

常見4線為SCLK、MOSI、MISO、CS_n，加共同GND；單端CMOS、通常PP，未被選取Target的MISO一般high-Z。1.8／3.3／5 V等門檻依器件，沒有通用SPI電壓／最大速率規格。CS多為低有效但可相反；SCLK閒置由CPOL定義，資料閒置值不固定。通常不採總線兩端並聯終端，部分高速板級介面用source series damping；值依板線與器件，不能當協定必要項。〔來源：S1、S2；終端設計判斷〕

| SPI mode | CPOL | CPHA | 閒置SCLK | 取樣緣 | 改變／推出資料緣 |
|---|---:|---:|---|---|---|
| 0 | 0 | 0 | 低 | 上升（第一緣） | 下降；第一bit須在第一緣前有效 |
| 1 | 0 | 1 | 低 | 下降（第二緣） | 上升 |
| 2 | 1 | 0 | 高 | 下降（第一緣） | 上升；第一bit須預先有效 |
| 3 | 1 | 1 | 高 | 上升（第二緣） | 下降 |

來源：S1 clock polarity／phase，S2。CPHA=0是leading edge sample、CPHA=1是trailing edge sample；不能把CPHA直接等同固定上升／下降緣而忽略CPOL。〔來源：S1〕

### 5.2 訊框、時序、參數與異常

CS有效開始、CS解除結束一筆常見transaction；全雙工時MOSI／MISO每個clock各移一bit，常見8／16-bit word、MSB first，也有LSB first及任意word長度。SPI本身沒有統一address、R/W、ACK/NACK、parity、CRC或長度欄位；這些由ADC、flash等裝置命令層定義。3-wire half-duplex共用資料線、daisy chain、dual／quad SPI應是另外的profile，不能硬套兩條單向data。〔來源：S1、S2〕

速率可從很低到數十MHz以上，最高依器件／負載，不能宣稱「SPI固定最高50 MHz」。解碼追蹤實際clock即可，經驗取樣率見§2.1。需檢查CS到第一clock setup、最後clock到CS hold、資料setup／hold及MISO clock-to-output；具體ns值必須使用器件資料表。CPHA=0首bit的CS setup、最後word截斷尤其容易造成整個byte錯位。〔來源：S1、S2；取樣倍率為實作建議〕

必要設定：clock／MOSI／MISO／CS通道、每線門檻／遲滯、CS極性、CPOL／CPHA、MSB／LSB、word bits、CS解除是否重置word、未接CS時的分段gap及half-duplex turnaround。可由clock閒置提出CPOL、用資料穩定性排名CPHA、估word對齊候選；沒有CRC或已知命令時，多個模式都可能產生看似合理的byte，不能自動確定。〔來源：S1、O3 §11.3；偵測限制及參數為實作建議〕

顯示`incomplete word`、`CS glitch`、`data unstable at sample edge`、`clock glitch`、`turnaround ambiguity`；若沒有裝置profile，不得自行報`NACK`或`CRC error`。未選取期間MISO浮動不是資料錯誤；同樣地，單線看到中間電壓只能標「疑似衝突／電氣不確定」，不能證明兩個Target同時驅動。〔來源：S1／S2、O3 §11.3.4；異常標示為實作建議〕

## 6. RS-232 與 UART

### 6.1 分層與實體層

UART是非同步字元格式，RS-232是線路電氣／介面標準，兩者不可視為相同電壓。TTL／CMOS UART腳位通常idle=高、start=低；RS-232資料線反相：mark邏輯1為負電壓，space邏輯0為正電壓，idle為負。常見TXD、RXD、GND；RTS／CTS等硬體流控線可另抓，沒有共用clock。各方向單端、主動驅動高低；不是OD總線，通常不裝兩端120 Ω終端。〔來源：U1〕

RS-232傳送器典型規範範圍±5至±15 V，接收器有效資料區為≤−3 V判1、≥+3 V判0，−3至+3 V不是保證有效區。離線可在0 V附近加遲滯後反相解碼，但這不等於receiver合規測試。若量的是收發器前的3.3 V UART，則應選CMOS門檻及正常極性，不能套±3 V；實際接收器遲滯／門檻依datasheet。〔來源：U1；解碼門檻為實作建議〕

### 6.2 字元、速率與鮑率容差

常見字元 `idle(1) → start(0,1 bit) → D0...D7 → optional parity → stop(1)`，LSB first；常見資料5–8 bits，也有9-bit模式，stop可1／1.5／2 bits，parity none／even／odd，部分器件有mark／space。沒有通用地址、ACK、CRC或多byte封包邊界；9th-bit address、ASCII換行或應用校驗是上層約定。例8N1共10 line bits，所以115200 baud的最高連續有效資料約11520 bytes/s。〔來源：U1、U2、O3 §11.5；速率算式為研究推導〕

常見baud有1200、9600、19200、38400、57600、115200，UART實作也可到1 Mbaud以上；原始RS-232的20 kbit/s歷史規範值不能當所有現代收發器的絕對上限，實際依器件與線長。二元NRZ時baud數值等於線上bit/s。解碼器先偵測start，再在0.5T檢查start、1.5T取D0、其後每T取一bit，最後檢查parity／stop；每個新start重新同步，不跨整段累積漂移。〔來源：U1、U2；離線步驟為實作建議〕

**鮑率容差不是一律±2%或±5%。** 理想8N1 stop中心約在start後9.5T，若累積誤差需小於0.5T，理論相對收發誤差約0.5/9.5≈5.3%；起始量化、noise、抖動與stop有效窗會縮小餘裕。U2以特定16× UART為例，更新晶片可有−4.4%／+5.6%的非對稱接收容差；這不是所有UART保證值。工程上可先把收發總差控制約2%作保守目標，但標示為設計建議，實際接收器容差待器件確認。〔來源：U2 §2；理論推導及2%目標為研究估計〕

### 6.3 設定、自動偵測與錯誤

必要設定：TX／RX或單data通道、232／CMOS電氣profile、反相、門檻／遲滯、baud、data bits、parity、stop bits、bit order（標準UART通常固定LSB）、封包分段gap／終止字元及break門檻。可由邊沿間隔估baud候選，以多字元的start／stop／parity一致性排名；不能把最短脈衝必定當1 bit，也不能從全0／全1等單一短資料確定baud／parity。〔來源：U2、O3／O4；參數與估測政策為實作建議〕

`framing error`＝預期stop取樣處不是mark；`parity error`＝資料及parity不符合設定；`false start/glitch`＝短脈衝或半bit檢查失敗；`break`＝持續space達所選器件／協定門檻；另顯示`baud mismatch suspected`、`truncated character`、`ambiguous format`。連續space可能同時造成framing及break，應保留關聯。硬體overrun、buffer overflow、實際接收器是否取錯值不能只由TXD／RXD波形證明。〔來源：U1／U2、O3；標示及可觀測性為研究判斷〕

## 7. RS-485

### 7.1 電氣層與極性

RS-485定義平衡差動收發器電氣，不規定UART、Modbus或其他訊框。常見2線half-duplex共享一對線、4線full-duplex用兩對線，另有共模參考／屏蔽設計。Driver啟用時主動驅動差動兩極，停用時high-Z；這是三態差動驅動，不是I2C式OD。匯流排端點常各120 Ω，依纜線阻抗選定，不能每節點都加120 Ω；開路／無人驅動時由failsafe／bias決定idle。〔來源：R1、R2〕

以明確指定的`Vdiff=V+−V−`表示，傳統接收器在≥+200 mV／≤−200 mV有保證判位，中間區不能假定可靠；標準典型共模工作範圍−7至+12 V、driver在規定54 Ω負載差動輸出至少約1.5 V。實際器件可能有更寬共模或內建failsafe門檻。A／B命名在設備與文件間可能相反，界面必須讓使用者選差動相減方向及邏輯反相，不能寫死「A高必為1」。〔來源：R1 electrical、R2 receiver；介面建議〕

### 7.2 速率、訊框、設定與錯誤

速率與纜線長度互相制約，R1的典型背景為短線可到10 Mbit/s、低速可達較長距離；不是任意1200 m和10 Mbit/s可以同時成立。現代器件上限另查datasheet。承載UART時沿用§6資料位／parity／stop與取樣率；RS-485本身沒有start／stop、位址、位元序、ACK、CRC或仲裁。多點誰可發送及換向由上層協定控制，不能把RS-485誤當CAN的非破壞仲裁。〔來源：R1、R2、U2〕

設定包含差動probe或兩類比通道、相減方向／deskew、差動門檻／遲滯、UART格式、half／full-duplex，以及可選DE／RE通道、封包gap、上層profile。可估baud／字元格式、找turnaround空檔；只看到0 V差動不能分辨high-Z、短路或互相抵消。若要Modbus RTU，另外設定slave／function／length、CRC-16及3.5字元等規則，這些都不是RS-485原生欄位；本研究不把未查核的Modbus時序直接納入基本485解碼。〔來源：R1／R2、O4；實作建議；Modbus完整規範待另案研究〕

異常分兩層：字元的framing／parity／break沿用UART；電氣層標`differential level uncertain`、`common-mode out of selected range`、`ringing/glitch`、`possible contention`；DE可觀測時再標過早釋放／換向重疊。上層CRC錯必須掛在相應profile，沒有上層設定時只能輸出byte stream，不能憑空報CRC error或NACK。〔來源：R1、R2、O4；標示為實作建議〕

## 8. CAN 與 CAN FD

### 8.1 實體層、位元時序與取樣

本節限定ISO 11898-2類的高速CAN／CAN FD，排除low-speed fault-tolerant CAN、single-wire CAN及CAN XL。線為CANH／CANL差動對及共模參考；典型5 V收發器recessive時兩線約2.5 V、差動約0 V，dominant時CANH約3.5 V、CANL約1.5 V、差動約2 V。邏輯0=dominant，1=recessive；總線idle為recessive，並不是UART的±電壓反相模型。〔來源：C3 driver／receiver／application；適用範圍限定〕

實際翻轉依器件；C3保證VID≤約0.5 V為recessive、≥約0.9 V為dominant，中間為過渡區，可先用約0.7 V附近遲滯解碼並反映成0／1，但不是通用CAN合規測試。兩個總線端點通常各120 Ω，或等效split termination；支線應短。CAN driver提供dominant／recessive wired-AND效果，dominant壓過recessive，不能當成兩個相反PP電源互撞，也不是I2C的單線OD電路。〔來源：C3 §7.7／§9；解碼門檻為實作建議〕

Classical CAN常用125／250／500 kbit/s及1 Mbit/s；CAN FD nominal arbitration phase仍常在≤1 Mbit/s，data phase可較快，常見2／5／8 Mbit/s，實際取決於收發器與網路。C3該產品基本型支援2 Mbit/s，G選項支援5 Mbit/s，不能拿單一產品上限當FD協定上限。解碼取樣依最快phase，見§2.1；CAN的sample point是位元時間內的位置，和示波器每秒取幾點是不同參數。〔來源：C1 §3、C3 features、C4；8 Mbit/s為常見工程配置，並非本表保證上限〕

位元時間分Sync_Seg、Prop_Seg、Phase_Seg1、Phase_Seg2；sample point在Phase_Seg1末端，SJW限制重同步修正。SOF提供hard sync，之後有效recessive→dominant緣用於resync；不能從SOF後固定等距切到整幀結束而完全忽略邊沿漂移。常見sample point約75–87.5%只是設定例，必須允許使用者選nominal／data兩套值或TQ配置；不能從波形唯一推回每個ECU的內部TQ／SJW。CAN FD transmitter的secondary sample point／TDC是內部傳送監看，與離線總線資料取樣不同。〔來源：C1 §3 bit timing；觀測限制為研究判斷〕

### 8.2 訊框、仲裁及 Classical／FD 差異

| 欄位 | Classical CAN | CAN FD |
|---|---|---|
| 開始／結束 | SOF dominant；EOF 7個recessive bits；intermission通常至少3 bits | 同核心邊界，bitrate切換需按FD規則 |
| identifier | 11-bit base或29-bit extended；不是節點地址 | 同11／29-bit主流格式 |
| 位元順序 | ID／欄位及每資料byte MSB first | 同；應用payload的多byte endian另由DBC／內容協定定義 |
| 類型控制 | RTR區分data／remote、IDE區分base／extended、保留bits、4-bit DLC | FDF表FD、BRS選速率切換、ESI表error state；沒有remote frame |
| 長度 | 0–8 bytes；DLC9–15在相應實作映射為8 bytes | DLC0–8→0–8；9→12、10→16、11→20、12→24、13→32、14→48、15→64 bytes |
| CRC | CRC-15，加delimiter | ≤16 bytes採CRC-17，20–64 bytes採CRC-21；ISO版另有stuff-count保護 |
| ACK | transmitter送recessive ACK slot，由任一正確接收者拉dominant；再接recessive delimiter | 同基本意義，ACK階段回nominal bitrate |
| 仲裁 | 逐位監看，送recessive而讀dominant者退讓 | nominal phase仲裁；data phase不做任意多發送者仲裁 |

來源：C1 §1.4、C2、C4。典型base data frame可寫成 `SOF → ID → RTR/控制 → DLC → Data → CRC → CRC delimiter → ACK slot → ACK delimiter → EOF → Intermission`；extended另有SRR／IDE及18-bit延伸ID。詳細控制位位置依base／extended、Classical／FD分別建表，不以一張固定header套全部。〔來源：C1 Figures1-3–1-8〕

低數值ID一般優先，但精確仲裁比較的是線上仲裁欄位，包括RTR、SRR、IDE等；相同base-ID時data frame可優先於remote、base可優先於相同前綴extended。只看到獲勝frame不能知道每個落敗節點及其欲送ID。ACK低只能證明至少有接收者接受，不能指定哪個ECU ACK；缺ACK可能因沒有其他接收節點，不是CRC一定錯。〔來源：C1 arbitration／frame結構、O3 CAN；被動觀測推論〕

FD的BRS=1時，在BRS位的sample point轉data timing，CRC delimiter的sample point切回nominal；跨界那個bit可能由兩種phase組成，不能只把整個BRS／delimiter按單一bit width切。BRS=0仍是FD長度／CRC格式，只是不切快時脈。CRC delimiter、ACK、EOF等固定形狀需做form check。〔來源：C1 §3及FD frame圖；實作解釋〕

### 8.3 Bit stuffing 與 CRC

Classical CAN從SOF到CRC sequence的可填充區，連續5個相同bit後插入1個相反stuff bit；接收時刪除stuff bit再解析欄位及算CRC。CRC delimiter、ACK、EOF等不是繼續套同一5-bit stuffing規則的區域。Error flag有意破壞一般編碼形狀，不應只顯示成大量stuff errors而漏掉error frame。〔來源：C1 bit stream／frame、C2〕

ISO CAN FD在SOF到data結束使用dynamic stuffing；CRC field使用另外的fixed stuff-bit安排，並帶3-bit Gray-coded stuff count及parity，不能用Classical去stuff後的資料直接套FD CRC。FD CRC的覆蓋資料包含特定stuff資訊，與Classical不同；完整計算還需要初始化、bit ordering及保護欄位的正確納入。non-ISO Bosch FD缺少後加的stuff-count保護，必須獨立profile，不能把相容性錯誤當線路CRC損壞。〔來源：C2、C1 §1.4.1；fixed stuffing逐bit位置及完整CRC參數實作前待規範／測試向量確認〕

已核對的多項式為Classical CRC-15：`x^15+x^14+x^10+x^8+x^7+x^4+x^3+1`；FD CRC-17：`x^17+x^16+x^14+x^13+x^11+x^6+x^4+x+1`；FD CRC-21：`x^21+x^20+x^13+x^11+x^7+x^4+x^3+1`。單有多項式不構成完整CRC實作規格；初值、增補、輸入域、stuff count與固定填充需一併驗證。〔來源：C2 CRC說明〕

### 8.4 設定、自動偵測與錯誤

必要設定：差動／CANH／CANL／RXD輸入profile、通道及極性、門檻／遲滯、nominal bitrate、data bitrate、兩套sample point、resync／SJW策略、Classical／ISO FD／non-ISO FD、glitch策略；若需內容解釋再載DBC、payload endian及signal scaling。11／29-bit可由IDE自動辨識，長度由DLC解出；baud可試候選並以stuff／CRC／form一致性驗證，但短資料或多組合理參數須保留歧義，不能聲稱自動還原全部節點設定。〔來源：C1 §1.4／§3、C2、O3；介面建議〕

應分`CRC error`、`stuff error`、`stuff-count/parity error`、`form error`、`ACK missing`、`error frame`、`overload frame`、`truncated frame`及`glitch/timing uncertainty`。Active error flag為6 dominant bits，後接8 recessive error delimiter；多節點重疊可延長dominant段，passive error flag在共用總線上不一定可辨。由CAN總線波形通常不能證明某節點的bit error、bus-off或error counter；FD ESI可提供傳送者狀態線索，但不是所有節點狀態。〔來源：C1 Figures1-8、error handling、C2、O3；標示與限制為研究判斷〕

## 10. 對本專案解碼實作的建議

### 10.1 通用架構

建議資料流為 **原始類比 → 邏輯位準（含遲滯與unknown）→ 邊沿／事件 → 協定狀態機 → 欄位／訊框 → 事件表／時間標註**。訊號處理、協定解析及UI分開，讓同一批邏輯事件可重跑多種協定候選；各層保存原始樣本索引及時間來源，避免解出錯誤後找不到對應波形。這是軟體架構建議，非上述協定規定。〔來源：本研究，依各協定不同實體層與原廠UI整理〕

1. **輸入／時間軸**：驗證單位、時間遞增、通道重疊範圍、取樣間隔、缺值／缺段，使用原始波形而非畫面抽點；差動運算先對齊與deskew，不能外插缺資料。時間計算使用區段相對時間降低浮點精度損失。〔來源：專案`docs/離線分析功能規格.md`現有時間／驗證策略；實作建議〕
2. **Analog→Logic**：每通道／差動pair獨立門檻、遲滯與極性，保存unknown區間、門檻附近裕量與原始edge候選；使用者可比較自動平台估計與手動值。初期不需要從電壓估測PP／OD當作前置必要條件。〔來源：§2與I3C可觀測性研究；實作建議〕
3. **Edge／Event**：chunk方式抽取轉換時間、方向、前後位準、脈寬與品質；跨chunk保留前態及待決脈衝。內插只能估交越時間，不能增加未擷取的脈衝或位元證據。協定濾波與原始事件分開，I2C的50 ns概念不能直接消掉I3C／SPI合法短脈衝。〔來源：I1、M2 mixed bus；分塊／品質為實作建議〕
4. **狀態機**：I2C／SPI依實際clock，UART依start重置字元時間，CAN用bit timing＋resync；I3C以SDR管理狀態統籌legacy／CCC／DAA／IBI／HDR子解碼器，地址與能力表有有效時間及已知／推測標記。〔來源：前述協定比較；實作建議〕
5. **結果層**：以專案既有`valid / limited / invalid`思路區分資料不足／設定歧義／已證實錯誤；另存protocol event如NACK、正常終止及仲裁，不把它們全變invalid。`CRC not checked`與`CRC mismatch`必須分開。缺頭尾時允許輸出partial並明列不能驗證哪些欄位。〔來源：專案既有狀態規格；本研究錯誤分類建議〕
6. **效能與重算**：GSa/s先線性掃描壓成edge/event、避免每bit讀整個GUI陣列；結果按設定hash／資料區段快取。繪圖降採樣只供顯示，解析使用完整事件；若要預先降取樣必須證明保留最短脈衝，不能只隔點。〔來源：專案取樣背景；實作建議〕

### 10.2 實作難度排序與理由

| 由易到難 | 理由與邊界 |
|---|---|
| 1. SPI基礎4線 | 外部clock和CS已給邊界；無標準CRC／仲裁。難點在可設定word／mode、缺CS及half-duplex應分期 |
| 2. UART／RS-232 | 單線狀態簡單；要處理baud估計、格式歧義、stop／parity／break、電壓反相 |
| 3. I2C | 要處理S／Sr／P、ACK、stretch、7／10-bit與截斷；clock已提供，比CAN時間復原容易 |
| 4. RS-485承載UART | 可復用UART，但增加差動、failsafe、三態及換向限制；若只做byte解碼可與UART同階，加入Modbus等另計 |
| 5. Classical CAN | clock復原／resync、仲裁欄位、stuffing、CRC、error／overload、partial frame復原 |
| 6. I3C SDR＋CCC／DAA／IBI／HJ／Reset | 同兩線但驅動／第9位意義／傳輸角色會變，還有地址能力時間狀態及共存；不能只是I2C加快 |
| 7. ISO CAN FD | 在Classical之上再處理兩套bit timing、跨界sample point、CRC17／21、fixed stuffing及ISO／non-ISO |
| 8. I3C HDR-DDR | 雙緣word、preamble／parity／CRC5、flow control與版本／能力狀態，需完整規範及向量 |
| 9. I3C HDR-BT、多lane及HDR-TSP／TSL | BT有block／lane／版本framing與CRC16／32；ternary要完全不同符號層且需完整會員規範。此列內各項相對難度仍依可得資料及測試設備而定 |

排序是以本專案「類比波形被動離線解碼、能解釋錯誤」為前提的工程評估，不是標準對複雜度的排名；I3C SDR與CAN FD的相對難度可隨團隊經驗調整。下一步討論I3C宜先定**Basic版號＋單lane SDR＋CCC／ENTDAA／IBI／Hot-Join＋Exit／Reset辨識**的明確範圍，再決定HDR-DDR；不把取得會員規範當作開始做SDR研究的必要條件。〔來源：本研究綜合判斷〕
