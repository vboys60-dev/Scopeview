## 3. P1：SPI

細部規格＝舊計畫 §4（全部照做）。以下為界線與偽代碼。

### 3.1 界線
- 做：CPOL／CPHA 四種模式、字組長 4–32、MSB／LSB、CS 高或低有效、無 CS 時以閒置時間分框、MOSI／MISO 任一或兩者。
- 不做：3 線半雙工、Dual／Quad、模式自動偵測、指令層、雙線時的逐 bit 顯示。
- SPI 沒有 ACK、CRC、同位：**絕不報 NACK／CRC 類錯誤**。原因碼只有 `incomplete truncated clk_phase unknown_bit no_cs`。
- 檔案：`web/spi_decode.py`、`web/spi_synth.py`、`web/spi_check.py`、`decode_spi.js`、`decode_protocols.js` +1 行、規格文件 SPI 節。不碰共享檔。

### 3.2 介面
```
ROLES = {'sclk': True, 'mosi': False, 'miso': False, 'cs': False}   BASE = 'sclk'
options: mode 0–3 (0)、bits 4–32 (8)、lsb (False)、cs_active 'low'|'high' ('low')、idle 秒|None (None)
options() 另查：mosi、miso 至少一條
```

### 3.3 偽代碼
```
run(edges, t1, mode, bits, lsb, cs_active, idle):
    cpol, cpha = mode >> 1, mode & 1
    rising = (cpol == cpha)                       # Mode 0/3 上升取樣，1/2 下降取樣
    ts = sclk 中方向符合、非 resync、時間 ≤ t1 的邊沿時間      # numpy 遮罩
    每條資料線 v[line] = levels_at(line, ts, t1)             # −1 = X

    若有 cs：
        spans = 由 cs 邊沿切出的有效區段 [(a, b, 起點已有效?, 終點仍有效?)]
        warnings += 'CS 外時脈 N 個'（N = 不在任何 span 內的取樣邊沿數，N>0 才加）
    否則：
        spans = idle 為 None → 整段一筆；否則相鄰 sclk 邊沿間隔 > idle 處切開
        每筆加資訊性 reason no_cs

    對每個 span：
        k = span 內的取樣索引
        f = frame(a, 'txn')
        有 cs 且 a 時刻 sclk 位準 ≠ cpol → reason clk_phase (warn)
        每 bits 個取樣切一個字組：
            對每條資料線：value = 依 lsb 組值；含 X → value=None, ok=False, 遮罩 label，frame 加 unknown_bit
            加 field(kind='mosi'|'miso', nbits=bits)
        剩餘 r 個取樣 (0 < r < bits) → 加一個 nbits=r 的 field，frame 加 incomplete
        起點已有效 → truncated（label「擷取開始時 CS 已有效，對齊未知」）
        終點仍有效 → truncated（剛好整數字組時不加 incomplete）
        bits_t／bits_v 只存主線（有 mosi 用 mosi，否則 miso）
        # ponytail: 雙線時不顯示逐 bit；需要時 bits 改存兩線
        超過 max_frames／max_fields → 停，truncated=True，warnings 加截止時間
```

### 3.4 驗證
- 手寫真值 H1：Mode 0、MOSI `10010110`、MISO `00101101` → 0x96／0x2D。
- 向量：舊計畫 §4.4 的 T1–T23（四種模式、LSB、W=16、W=12、兩筆交易、12 取樣 → 1 字組＋4 位 incomplete、CS 起點已有效、NaN → X、無 CS 各情況、只有 MOSI、視窗結尾 CS 仍有效）＋CS 高有效、固定電位線。
- `--mutations`：取樣邊表只看 CPHA（Mode 2／3 向量必紅）、位元順序反轉（LSB 向量必紅）、滿 W 位不歸零（無 CS 向量必紅）。
- 沒有實機資料，也沒有 XML；結論只能寫「合成向量通過」。

## 4. P2：CAN（Classical 2.0A／B）

細部規格＝舊計畫 §6。準則審查帶來的差異只有一條：**intermission 是 3 位**（`CAN.xml` 寫 2 位，不照 XML）。

### 4.1 界線
- 做：標準／擴充 ID、data／remote、位元填充、CRC-15、form／stuff／crc／no_ack、錯誤（過載）旗標、FDF=1 標示後跳過（P4 才細解）。
- 不做：受 SJW 限制的重同步、位元率自動偵測、錯誤與過載旗標的區分、DBC、CAN XL。
- 檔案：`web/can_decode.py`（狀態機）＋`web/can_fields.py`（欄位切割、CRC、去填充；預期會超過 300 行所以先拆）、`web/can_synth.py`、`web/can_check.py`、`decode_can.js`、+1 行、規格文件 CAN 節。

### 4.2 介面
```
ROLES = {'can': True, 'canl': False}   BASE = 'can'   DIFF = {'canl': 'can'}
options: bitrate 必填 (500000)、sample_point 50–95 (75)、dominant_high (True)
```

### 4.3 偽代碼
```
crc15(bits):  crc = 0
    for b in bits: crc = ((crc << 1) ^ 0x4599) & 0x7FFF if ((crc >> 14) ^ b) else (crc << 1) & 0x7FFF

run(edges, t1, bitrate, sample_point, dominant_high):
    T = 1/bitrate ; sp = sample_point/100
    state = HUNT                                   # 需先看到 ≥11 T recessive
    逐個 recessive→dominant 邊沿 e：
        若不在 frame 內：
            量 dominant 段長 L：L ≥ 6T → error_flag frame（t1 = 其後 8T recessive 結束）→ HUNT
            否則 HUNT 條件滿足（或剛完成一框且已過 intermission 第 3 位）→ 開框，t_sync = e
    框內逐位：
        t = t_sync + (k + sp)·T ；超過 t1 → truncated，收框
        b = levels_at(can, t) 經 dominant_high 轉成 0=dominant／1=recessive；−1 → unknown_bit，收框回 HUNT
        重對齊：框內每個有效 r→d 邊沿（之後 dominant 持續 ≥ 0.5T）
                e = (t_edge − t_sync)/T − round(...) ; t_sync += e·T ; |e| > 0.25 → timing (warn)
        去填充（SOF 到 CRC 末位）：連續 5 個相同後下一位必須相反，相反 → 丟棄並在 bits 標 2；相同 → stuff，收框
        欄位：SOF | ID11 | RTR/SRR | IDE | (IDE=1: ID18 | RTR | r1 | r0)(IDE=0: r0) | DLC4 | DATA min(DLC,8)·8 | CRC15
              | CRC del | ACK | ACK del | EOF7
        r0（基本）或 r1（擴充）為 recessive → kind fd、reason fd_unsupported → HUNT        # P4 改寫這一步
        CRC del／ACK del／EOF 第 1–6 位 dominant → form
        ACK slot recessive → no_ack (warn)
        crc15(去填充後 SOF..DATA) ≠ 收到的 CRC → crc
    錯誤收框後：從 t1 起掃 ≥6T dominant → error_flag frame
    每位取樣點數 < 8 → warnings『取樣不足』
```

### 4.4 驗證
- 手寫真值：舊計畫的 51 位 stuffed 字串（CRC 0x36B7）、CRC 檢查值 `"123456789"` → 0x059E。
- 向量：舊計畫 §6.4 全部；`--mutations` 五項（填充門檻 5→6、多項式改一位、拿掉重對齊、DLC>8 不截 8、框尾也要求 11 位 idle）。
- **實機參考向量**：`X6000A-解碼/CAN/x6000can.csv`（212 列、209 列有 CRC，已實算 208 列 CRC-15 吻合）。做法是「CSV 列 → 合成波形 → 解回來逐欄相等」。這是閉環測試，只證明欄位切割與 CRC，不證明判位與時序。
- **開工前先做的一件事**：`x6000can.h5` 約 2.6 點／位元，不足以可靠解碼。先請使用者用 RAW 模式重錄一段（目標 ≥ 8 點／位元），錄不到就把「實機波形未驗」寫進規格與 HANDOFF，不擋開工。

## 5. P3：RS-485

### 5.1 界線
- RS-485 只是實體層；字元框架與錯誤判定完全等於 UART。不新增協定名、不新增模組。
- 做：`uart` 增加兩個可省的負端角色，讓工具內做 A−B。
- 不做：Modbus RTU（3.5 字元間隔、CRC-16）、DE 方向／衝突／回音偵測、半雙工收發歸屬。
- **極性不寫死**：TIA-485 定義 A 低於 B 為 mark，但多數收發器晶片的 A／B 命名與標準相反。沿用既有 `invert` 選項，並靠既有的「閒置偏低，可能需反相」提示。
- 檔案：`web/uart_decode.py`（+3 行左右，現 283 行，不會超限）、`web/uart_synth.py`（加差動輸出）、`web/uart_check.py`（加向量）、`decode_uart.js`（角色與說明文字）、規格文件 UART 節補一段。共享檔見 §1.4。

### 5.2 介面變更
```
ROLES = {'tx': True, 'rx': False, 'tx_n': False, 'rx_n': False}
DIFF  = {'tx_n': 'tx', 'rx_n': 'rx'}          # 共用層已會做 tx − tx_n；thresholds 鍵自動排除負端
options() 另查：rx_n 存在時 rx 必須存在
```
`run()` 不改：它收到的已經是相減後的邏輯線。

### 5.3 偽代碼（只有合成器與檢查是新的）
```
uart_synth.differential(trans, vcm=2.5, vod=2.0):
    每個 (t, 'tx', level) → (t, 'tx', vcm ± vod/2) 與 (t, 'tx_n', vcm ∓ vod/2)
    三態閒置：兩線都回 vcm（差動 ≈ 0，落在遲滯帶內，維持前態）

uart_check 新增：
    V1 差動 A/B＋共模 +7 V → 與單端向量逐欄相等
    V2 A/B 對調 → 不勾反相時出現「可能需反相」警告；勾反相後逐欄相等
    V3 字元之間三態（差動 0 V）→ 結果不變
    V4 只給 tx＋tx_n、不給 rx → 可解
    mutation：DIFF 拿掉 → V1 必紅（共模偏移使單端門檻失準）
```

### 5.4 風險
- 三態閒置時差動電壓若在遲滯帶外飄動，會產生假起始位。目前不處理，規格寫明「failsafe 偏壓不足的匯流排可能出現 unsynced」；有實機資料再決定。
- 自動門檻以平台中點估計，差動 ±2 V 時中點約 0 V，可用；手動門檻建議 ±0.2 V。

## 6. P4：CAN FD（ISO 11898-1:2015）

### 6.1 界線
- 這一項推翻舊計畫 Q1「不做」。**先決條件：至少一筆外部真值**（實機擷取＋示波器解碼結果，或公開向量）的 CRC 對上才算完成；拿不到就照做但規格與 UI 摘要標「未經外部驗證」。
- 做：ISO FD（有 stuff count）、BRS=0／1、DLC 0–15（最長 64 byte）、CRC-17／21、固定填充位、stuff count＋同位。
- 不做：non-ISO（Bosch 原版，無 stuff count）、CAN XL、收發器延遲補償、資料段取樣點自動估計。
- 未填 `data_bitrate` 時維持現行為（kind `fd`＋`fd_unsupported`，跳到下一筆）。
- 檔案：新檔 `web/can_fd.py`（FD 的欄位、CRC、固定填充；由 `can_decode` 在 FDF=1 時呼叫）、`can_synth.py`／`can_check.py` 追加、`decode_can.js` 加兩個選項。

### 6.2 介面變更
```
options 追加：data_bitrate（None＝不解 FD）、data_sample_point 50–95 (75)
新 reason：stuff_count ；新 field kind：sbc ；固定填充位錯誤歸 form
```

### 6.3 偽代碼
```
DLC_LEN = [0..8, 12, 16, 20, 24, 32, 48, 64]
GRAY = {0:0b000, 1:0b001, 2:0b011, 3:0b010, 4:0b110, 5:0b111, 6:0b101, 7:0b100}

crc_fd(bits, n):                       # n = 17 或 21
    poly = 0x3685B if n == 17 else 0x302899 ; crc = 1 << (n − 1)      # ISO 初值＝最高位為 1
    逐位同 crc15，寬度 n

FD 分支（FDF=1 之後）：
    欄位：res(=0，否則 form) | BRS | ESI | DLC4 | DATA DLC_LEN[dlc]·8
    位元時間：
        BRS=1 → BRS 位長 = sp_n·Tn + (1 − sp_d)·Td ；之後每位 Td、取樣於 sp_d
                 CRC delimiter 位長 = sp_d·Td + (1 − sp_n)·Tn ；之後回 Tn
        BRS=0 → 全程 Tn
    動態填充：SOF 到 DATA 末位，規則同 Classical；n_stuff = 動態填充位數
        邊界：DATA 末尾剛好 5 個同值位 → 不插動態填充位（下一位就是固定填充位，且不計入 n_stuff）
    CRC 欄位（固定填充）：之後以 4 位為一組，每組前面有一個固定填充位 FSB
        FSB | SBC(Gray3 + 偶同位1) | FSB | CRC[4] | FSB | CRC[4] | …      # CRC-17 共 6 個 FSB，CRC-21 共 7 個
        FSB 必須是前一個線上位元的反相，否則 form
    檢查：
        SBC 的 Gray ≠ GRAY[n_stuff mod 8] 或同位錯 → stuff_count
        n = 17（DLC_LEN ≤ 16）或 21
        crc_fd(SOF..DATA 的線上位元（含動態填充位）＋ SBC 4 位，不含任何 FSB) ≠ 收到的 CRC → crc
    CRC del（接受 1–2 位 recessive）| ACK（接受 1–2 位 dominant）| ACK del | EOF7 ：同 Classical
```

### 6.4 驗證
- 手寫真值：一筆 BRS=0、DLC=1 的訊框逐位手算（含 FSB 與 SBC）。
- 向量：BRS=0／1 × DLC 8／9／15；動態填充落在 DATA 末位；n_stuff 跨 mod 8（8 個填充位 → Gray 000）；FSB 錯 → form；SBC 錯 → stuff_count；未填 data_bitrate → fd_unsupported；FD 與 Classical 混排。
- `--mutations`：CRC 把固定填充位算進去、初值改 0、SBC 用二進位而非 Gray、BRS 切換點改在位元邊界、DATA 末尾 5 同值時多插動態填充位——各自必紅。
- 風險：合成器與解碼器由同一份理解寫成，閉環測不出共同誤解。這就是需要外部真值的原因。

## 7. P5：eSPI

### 7.1 界線
- 依 Intel eSPI 規格；`eSPI.xml` 是 Rev 0.75，只取 opcode／回應碼／欄位長度當列舉來源。
- **取樣固定**：時脈上升緣取樣（不是可設定的 CPOL／CPHA）。CRC8：多項式 0x07、初值 0、MSB first。
- 做（第一版）：單線 I/O 模式；指令與回應的切分、WAIT_STATE、Status、兩段 CRC8；opcode 與回應碼命名。
- 第二版（第一版通過後才做）：Dual／Quad I/O（`io_mode` 手動指定）；PUT_PC／PUT_OOB／PUT_FLASH_C 的 header 內欄位細解（Tag、Length、Address）。
- 不做：Alert（CS 高時 IO1 拉低）、依 GET／SET_CONFIGURATION 內容自動切換 I/O 模式、通道層語意（VW index 命名、Flash 存取解讀）、CRC 檢查關閉的情況自動判斷。
- 檔案：`web/espi_decode.py`、`web/espi_table.py`（opcode 表與長度規則）、`web/espi_synth.py`、`web/espi_check.py`、`decode_espi.js`、+1 行。共享檔見 §1.4。
- 重用：SPI 的「依 CS 切區段＋取樣邊取位」函式直接 import，不複製。

### 7.2 介面
```
ROLES = {'cs': True, 'clk': True, 'io0': True, 'io1': True, 'io2': False, 'io3': False}   BASE = 'clk'
options: io_mode 'single'|'dual'|'quad' ('single')、crc (True；False 時不驗 CRC，只顯示)
frame kind：cmd（一筆 CS 區段＝指令＋回應）、reset、partial
field kind：opcode hdr addr data resp status crc wait
reasons：crc_cmd crc_resp unknown_opcode no_response defer fatal reserved_bit truncated incomplete unknown_bit
```

### 7.3 偽代碼
```
crc8(bytes): crc = 0 ; 每 byte: crc ^= b ; 8 次 (crc = (crc << 1) ^ 0x07 if crc & 0x80 else crc << 1) & 0xFF

CMD_LEN(opcode, 已讀位元組) -> 指令總長（含 CRC），或 None＝還要多讀：
    GET_STATUS 25、GET_PC 01、GET_NP 03、GET_VWIRE 05、GET_OOB 07、GET_FLASH_NP 09 → 2
    GET_CONFIGURATION 21 → 4（addr16）；SET_CONFIGURATION 22 → 8（addr16 + data32）
    PUT_VWIRE 04 → 3 + 2·(count + 1)，count 在第 2 個位元組低 6 位
    PUT_PC 00／PUT_NP 02／PUT_OOB 06／PUT_FLASH_C 08 → 由 cycle type 與 Length12 決定（第二版細解；第一版只算長度）
    Short 40–4F → 由低 2 位決定資料長 1／2／4，位址 16 或 32 位        〔長度表實作前對規格逐列核對〕
    RESET FF → 特例：16 個時脈全 1，無 CRC、無回應
    其他 → unknown_opcode：整段以原始位元組列出，不驗 CRC

run：
    spans = CS 低有效區段（重用 SPI）
    對每個 span：
        單線：cmd_bits = io0 在上升緣的位元；resp_bits = io1 在上升緣的位元
        （第二版：dual 每時脈 2 位 io1:io0、quad 每時脈 4 位 io3..io0，MSB 先）
        cmd = 依 CMD_LEN 取位元組 ；crc8(cmd[:-1]) ≠ cmd[-1] → crc_cmd
        跳過 TAR：2 個時脈週期
        resp：先吃掉連續的 WAIT_STATE（0x0F，各成一個 wait field，不進 CRC）
              回應碼低 4 位：8 ACCEPT、1 DEFER → defer、2 NON_FATAL、3 FATAL → fatal；FF NO_RESPONSE → no_response，收框
              依指令種類取回應資料（GET_* 才有）→ Status16（低位元組先送）→ CRC
              crc8(回應碼..Status) ≠ CRC → crc_resp
        Status 保留位不為 0 → reserved_bit
        區段結束時位元組未湊滿 → incomplete；CS 起點／終點在擷取外 → truncated
```

### 7.4 驗證
- 已實算的 CRC8 參考值（寫進手寫真值）：`"123456789"` → 0xF4；`25` → 0xFB（GET_STATUS 指令＝`25 FB`）；`21 00 04` → 0x34；`08 0F 03` → 0x9B（ACCEPT＋Status 0x030F）。
- 向量：GET_STATUS 完整交易、GET／SET_CONFIGURATION、PUT_VWIRE count=0 與 count=3、兩個 WAIT_STATE 後 ACCEPT、DEFER、NO_RESPONSE、指令 CRC 錯、回應 CRC 錯、RESET、未知 opcode、CS 中途截斷。
- `--mutations`：CRC 初值改 0xFF、WAIT_STATE 算進 CRC、Status 位元組順序對調、TAR 少跳一個時脈、取樣改下降緣——各自必紅。
- 沒有實機資料。若能取得，目標是 Intel 平台開機階段的 GET_CONFIGURATION 序列。

## 8. P6：USB PD

### 8.1 界線
- 做：CC 線 BMC 解碼、前導碼、4b5b、SOP*／Hard Reset／Cable Reset、Message Header、Data Object 以 32 位原值列出、CRC32、EOP。訊息型別名稱取 `USB_PD_31_15.xml` 的列舉（R3.1）。
- 第二版：Source_Capabilities／Request 的 PDO 欄位拆解、Extended 訊息（Extended Header、Chunk）。
- 不做：GoodCRC 逾時與 MessageID 配對、協定狀態機合規、VDM／EPR 內容解讀、CC1／CC2 自動辨識（使用者選通道）、VBUS 關聯。
- 檔案：`web/usbpd_decode.py`（BMC＋分框）、`web/usbpd_fields.py`（4b5b 表、header、訊息名稱）、`web/usbpd_synth.py`、`web/usbpd_check.py`、`decode_usbpd.js`、+1 行。共享檔見 §1.4。

### 8.2 介面
```
ROLES = {'cc': True}   BASE = 'cc'   REQUIRE_EDGES = True
options: bitrate（None＝由前導碼量測；可手動填，規格 300 kbit/s ±10%）
frame kind：control data extended hard_reset cable_reset partial
field kind：sop header obj crc eop
reasons：crc invalid_5b bad_eop bad_sop sampler preamble reserved truncated
```
實體層現實：位元率容差 ±10% 且各埠不同，所以預設由每筆封包自己的前導碼量測，手動值只當校正旋鈕。

### 8.3 偽代碼
```
4b5b（5 位，LSB 先送）：
    0:11110 1:01001 2:10100 3:10101 4:01010 5:01011 6:01110 7:01111
    8:10010 9:10011 A:10110 B:10111 C:11010 D:11011 E:11100 F:11101
    Sync-1 11000  Sync-2 10001  Sync-3 00110  RST-1 00111  RST-2 11001  EOP 01101
SOP*（4 個 K 碼）：
    SOP = S1 S1 S1 S2 ；SOP' = S1 S1 S3 S3 ；SOP'' = S1 S3 S1 S3
    Hard Reset = R1 R1 R1 R2 ；Cable Reset = R1 S1 R1 S3
    SOP'_Debug = S1 R2 R2 S3 ；SOP''_Debug = S1 R2 S3 S2

run(edges, t1, bitrate):
    dt = 相鄰邊沿間隔
    封包切分：間隔 > 3·UI_名義 處切開（封包之間 CC 靜止）
    對每個封包：
        UI = bitrate 給定 → 1/bitrate；否則取前導碼區間隔的中位數推得（前導碼 0101…：間隔樣式 T, T/2, T/2, …）
             UI 不在 300k ±20% → warnings
        BMC 判位（逐間隔，UI 以滑動平均跟隨）：
            d ≥ 0.75·UI → 位元 0
            d < 0.75·UI 且下一個間隔也 < 0.75·UI → 位元 1（吃掉兩個間隔）
            其他 → sampler，收框（partial）
        最後一位沒有收尾邊沿：以「擷取結束或靜止 > 1.5·UI」補上
        前導碼：找到連續交替位元後，在其結尾附近逐位偏移找第一個合法 SOP*（4 個 K 碼）
            # ponytail: 要求 4 個 K 碼全對；規格允許 4 中 3，遇到實機漏框再放寬
            找不到 → preamble 或 bad_sop
        Hard Reset／Cable Reset → 只有 ordered set，收框
        之後每 5 位查表成 nibble（LSB 先），直到 EOP；查不到 → invalid_5b；到封包尾沒有 EOP → bad_eop
        bytes = nibble 兩兩合併（低 nibble 先）
        header = bytes[0:2] little-endian：
            MsgType[4:0] | DataRole[5] | SpecRev[7:6] | PowerRole／CablePlug[8] | MsgID[11:9] | NumDO[14:12] | Extended[15]
        kind = extended（Extended=1）／data（NumDO>0）／control
        長度應為 2 + 4·NumDO + 4；不符 → truncated 或 bad_eop
        zlib.crc32(header + objects) ≠ CRC（little-endian）→ crc
        SOP 類型不允許的 MsgType → bad_sop ；保留位不為 0 → reserved
```

### 8.4 驗證
- 已實算的參考值：header `41 01`（GoodCRC，MsgID 0）→ CRC32 = 0xDFBC5C2D，線上順序 `2D 5C BC DF`；殘值 `zlib.crc32(data + crc_le)` = 0x2144DF1C。
- 手寫真值：GoodCRC 一筆，從 nibble → 5b → BMC 轉換逐步手寫，不經合成器。
- 向量：Source_Capabilities（NumDO=1 與 7）、Request、Accept、PS_RDY、SOP'、Hard Reset、Cable Reset、位元率 270k 與 330k、CRC 錯、無效 5b 碼、缺 EOP、擷取起點在封包中間、兩筆封包緊鄰。
- `--mutations`：5b 位元順序反轉、nibble 合併順序對調、CRC 改大端、BMC 門檻 0.75 改 0.5 或 1.0、UI 不跟隨（330k 向量必紅）。
- 實機：建議使用者錄一段充電器的 Source_Capabilities → Request → Accept → PS_RDY，取樣率 ≥ 10 MSa/s（每位元 ≥ 33 點）。這是九個協定裡最容易取得實機資料的一項。

## 9. P7：I3C HDR-DDR

### 9.1 界線
- 排最後：沒有實機波形，CRC5 與同位的理解只有規格依據（MIPI I3C Basic v1.1.1 §5.2.2），未經向量驗證。
- 做：ENTHDR0 之後到 HDR Exit／Restart 樣式之間的 HDR-DDR 字組：Command、Data、CRC；P1／P0 同位、CRC5、preamble 合法性。
- 不做：HDR-TSP／TSL（三元符號）、HDR-BT、多線、v1.1.1 的提前終止等新增行為。
- 檔案：新檔 `web/i3c_hdr.py`；`i3c_decode.py` 只在現有產生 `hdr` frame 的地方改成呼叫它（該檔已 299 行，只能換行不能加行）；`i3c_synth.py`／`i3c_vectors.py`／`i3c_check.py` 追加；`decode_i3c.js` 加欄位文字。

### 9.2 偽代碼
```
parity(payload16):  p1 = D15^D13^…^D1 ；p0 = D14^D12^…^D0 ^ 1
crc5(payload16 列表): crc = 0x1F ；逐位 MSB 先，多項式 x⁵+x²+1

decode_hdr(scl, sda, t_start, t_end):
    ts = t_start..t_end 內 SCL 的所有邊沿（上升與下降都取樣）
    bits = levels_at(sda, ts)
    逐字組：
        pre = 2 位
        第一個字組：pre 必須 01 → Command：RnW1 | Cmd7 | Addr7 | Rsv1 | P1 | P0（20 位）
        之後：pre 10／11 → Data：Data16 | P1 | P0
              第一個 Data 的 pre：10 = ACK、11 = NACK → hdr_nack，收框
              後續 Data 的 pre：11 = 續傳、10 = 中止
              pre 01 → CRC：Token4（必須 0xC）| CRC5 | 之後為 setup 位
        P1／P0 不符 → hdr_parity
        crc5(Command 與所有 Data 的 16 位 payload) ≠ CRC5 → hdr_crc
        Token ≠ 0xC 或 pre 不在合法集合 → hdr_preamble
    位元不足一個字組 → truncated
```

### 9.3 驗證
- 手寫真值：一筆寫入（Command＋1 個 Data＋CRC）逐位手算。
- 向量：寫 1／多字組、讀、NACK、中止、同位錯、CRC 錯、Token 錯、HDR Restart 後第二筆。
- `--mutations`：P0 不反相、CRC 初值改 0、CRC 輸入含 preamble、只在上升緣取樣——各自必紅。
- 既有 I3C 指紋 F1–F5 不得改變。
